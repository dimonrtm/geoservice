# Осведомлённость Редактора И Восстановление Сохранения

Принятая проекция взаимодействия редактора, а не новая серверная state machine, entity или замена lifecycle `EditVersion`. Основание — ответы 3, 6–13 исследования.

| Известное состояние | Событие наблюдателя | Принятое поведение |
| --- | --- | --- |
| Сохранённое состояние прочитано | Редактор изменил линию | Локальная несохранённая попытка |
| Локальная попытка | Редактор отправил Save | Ожидание результата; идентичность намерения удерживается |
| Ожидание | Получен подтверждённый успех | Подтверждение операции; согласование с актуальными данными |
| Ожидание | Получен подтверждённый отказ | Исправление попытки или сравнение при stale; без скрытой mutation |
| Ожидание | Ответ потерян | Результат неизвестен; новые Save/Revert этой версии приостановлены в интерфейсе |
| Результат неизвестен | Повтор прежнего намерения дал terminal result | Установлен прежний исход; актуальные данные читаются отдельно |
| Результат неизвестен | Идентичность/доступ восстановить нельзя | Разбор без догадки об успехе или новом автоматическом Save |
| Получено старое подтверждение | Есть более свежая правка | Подтверждение остаётся историческим; актуальная карта не откатывается |
| Локальная попытка | Явный Cancel | Возврат к последнему сохранённому представлению без серверной операции |
| Сохранённое изменение | Явно подтверждён Revert | Новое намерение сохранить baseline; применим тот же цикл ожидания/восстановления |

Неизвестность допускает несколько фактических исходов: запрос ещё не исполнен, транзакция откатилась, либо результат уже зафиксирован, но ответ потерян. Из состояния наблюдателя нельзя вывести наличие durable `running`/`OutcomePending` в БД.

Повторный ответ на старое действие и свежий readback выполняют разные роли. `CommandId` защищает повтор намерения; `DraftVersionToken` — новое изменение относительно текущей версии. Не появляется отдельный aggregate или распределённая блокировка рабочей версии.

Политика принята, диаграмма согласована со старой моделью по [[Wiki/conflicts/2026-10-11-save-outcome-observer-vs-operation]]. Она не доказывает реализацию API/UI.

## Пограничные переходы 2026-10-16

Источник: [[RAW_inputs/research_results/2026-10-16-utility-gis-editor-recovery-use-case-research]]. Уточняется только наблюдатель; server state не расширяется.

| Ситуация | Переход и ограничение |
| --- | --- |
| Доступ вернулся | Явно подтвердить выяснение прежнего исхода; новый intent не отправляется автоматически. |
| Success подтверждён, current недоступен | Сохранить историческую квитанцию, повторять чтение; новая mutation запрещена. |
| Current изменился после подтверждения Revert | Вернуться к сравнению и новому подтверждению. |
| Работа закрыта, исход доказан | Завершить разбор с явным запретом продолжения; не переоткрывать lifecycle. |
| Current совпадает с candidate | После разрешения прежнего исхода отказаться от лишней mutation; авторство не выводится из совпадения. |
| Принудительно прекращён доступ | Остановить действия, скрыть приватные данные; не выдавать local draft за sent intent. |
| Несколько окон отправили действия | Установить каждый исход отдельно; закрытие окна не отменяет операцию. |

Переход к новым правкам регулирует [[Wiki/specifications/editing_resumption_allowed]].
