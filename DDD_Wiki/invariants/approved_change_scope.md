# Публикация проверенного состава правки

Редактор может представить к рассмотрению определённый состав изменений после проверки правил, топологии и разрешения конфликтов. В официальный слой попадают только те изменения, для которых пройдена проверка и получено утверждение. Опубликованная правка и её запись в истории относятся к этой рабочей версии. [Исходный цикл](../../RAW_inputs/documents/UtilityGisEditor.md#базовые-и-продвинутые-workflows) · [Граница рабочей версии](../aggregates/network_edit_version.md).

| Условная проверка | Ожидаемый предметный результат |
| --- | --- |
| При проверке соединения обнаружена ошибка. Редактор изменил узел и сразу пытается передать правку на публикацию. | Исправленный состав проходит повторную проверку правил и топологии и затем утверждение. До публикации в официальной сети доступна прежняя связь. |
| Измеренный участок можно проверить независимо от спорной врезки. Утверждена только геометрия участка. | В официальном слое видна измеренная геометрия. Врезка ожидает своего основания, через неё нельзя построить путь. |
| Границу достоверной съёмки нельзя выделить без нарушения обязательной топологической проверки. | Изменение остаётся в рабочей версии. Сокращение публикуемого объёма допустимо, только когда остающийся фрагмент сам проходит проверки. |
| Объём утверждён и опубликован, мобильный клиент ещё не получил обновление. | Официальная сеть уже содержит опубликованный состав. Получение копии полевым клиентом относится к обмену. |

Второй и третий примеры применяют правило GeoService по NET-09. Из изменения смежного узла другим редактором после утверждения пока нельзя вывести обязательный объём повторной проверки. Это отдельный вопрос NET-06.
