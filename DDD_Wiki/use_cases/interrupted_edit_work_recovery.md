# Разобрать прерванное редактирование и безопасно продолжить работу

## Действующая редакция условной организации — 2026-10-13

Принято агентом по прямому поручению пользователя принять решения за условную организацию. Confidence high относится к фиксации решения, не к эмпирической проверке. Статус active не подтверждает реализацию. Эта редакция заменяет прежние ожидания реальных назначений и принятия предложений ниже.

## Участники и цель

Editor сохраняет намерение, поддержка выясняет исход, распорядитель данных определяет влияние источника, координатор проверяет scope, Reviewer проверяет доказательства отдельным проходом. Агент исполняет обязанности условной организации; новые auth roles/aggregate/context не вводятся.

## Основной сценарий

1. Различить неизвестный исход, дефект источника и неподтверждённое качество.
2. Удержать намерение и ограничения. После одного неудачного безопасного цикла или 5 минут открыть карточку; при потере identity/общем сбое/исходном дефекте — сразу.
3. Поддержка принимает карточку за 15 минут активной сессии, классифицирует за 60. Передача явная, без чужих credentials/CommandId.
4. Получить durable исход прежнего действия и отдельно current. Без доказанного исхода не допускать новое намерение как обход.
5. Для дефекта источника определить зависимости, сохранить старую версию, сравнить исправленный источник и намерение. При затронутом baseline нужен отдельно реализуемый новый контекст, не скрытый rebase.
6. Распорядитель формирует разрешение с доказательствами, Reviewer проверяет, координатор подтверждает AOI при необходимости. Editor явно выбирает продолжение при всех guards.
7. Отдельно оценить evidence по [[Wiki/specifications/simulated_line_positional_acceptance]]. Учебный pass не меняет автоматически backend-статус и не разрешает review/post.

## Границы согласованности

Save остаётся атомарным в EditVersion. Карточка — ручной процесс, не долгая транзакция, persisted pending state или новая серверная блокировка. Неизвестный исход ограничивает запись затронутой версии; независимая работа разрешена.

## Альтернативы

Нет доказательств — разбор открыт. Нет принятой передачи — владелец прежний. Нужен неподдерживаемый restart — только документированное сравнение до отдельной реализации. Evidence неполно — UNVERIFIED. Контекст закрыт — установление исторического исхода не разрешает запись.

## Критерии результата

Один владелец и следующий шаг, подтверждённый исход отдельно от current, явная область влияния и доказательство разрешения. История/доступ не обходятся. Девять проверочных сценариев заданы в новом RAW; продуктовые тесты не выполнялись. Решения приняты, реализация отслеживается в FU-2026-10-13-004.

# Разобрать прерванное редактирование и безопасно продолжить работу

Предлагаемая проекция ответов 1–12. Организационные шаги не являются реализованными командами, новой серверной state machine или полномочием изменять immutable baseline. Приоритет сохраняют принятые инварианты `WorkOrder` / `EditVersion`.

## Участники и ответственность

Editor удерживает намерение; ответственный за разбор устанавливает судьбу действия; ответственный за данные оценивает источник и влияние; специалист по измерениям оценивает применимость доказательств. Это обязанности, не новые роли авторизации. Назначенные люди и каналы отсутствуют.

## Основной сценарий

1. Определить вид препятствия: неизвестный исход, дефект источника либо неподтверждённое качество. Они могут сосуществовать и не подменяют друг друга.
2. Удержать контекст и действующие ограничения. Не создавать новое намерение автоматически.
3. Передать разбор с явным принятием ответственности, если обычное безопасное восстановление недостаточно.
4. Для неизвестного исхода получить доказательство результата конкретного действия и отдельно прочитать current. При неустановленном исходе продолжить разбор.
5. Для дефекта источника определить зависимые работы, организовать отдельное исправление и проверить применимость прежних правок. Не изменять основание существующей версии задним числом.
6. Зафиксировать допустимое основание продолжения и оставшиеся ограничения; редактор явно подтверждает дальнейшее намерение при действующих access/lifecycle/token guards.
7. Позиционное подтверждение оценивается отдельно. Разрешение продолжить редактирование не означает готовность review/post.

## Границы согласованности

Сохранение остаётся атомарной операцией существующего агрегата. Разбор может переживать смену исполнителя и несколько операций, но это не основание держать DB transaction или вводить длительную серверную блокировку. Организационная передача не меняет владельца `CommandId` и не обходит назначение наряда.

## Альтернативы и незакрытые переходы

- Нет доказательства исхода — не трактовать отсутствие записи как доказанный отказ.
- Нет получателя — передать владельцу проекта для назначения, сохранив ограничение затронутой работы.
- Исправление требует нового baseline — переход к новому контексту должен быть отдельно спроектирован; текущие Open/reopen/Save не объявляются таким механизмом.
- Подтверждена только часть линии — не повышать качество всей линии автоматически.

## Критерии наблюдаемого результата

У каждого открытого разбора есть владелец и следующий шаг; сохранены различия между намерением, историческим результатом и current; известны затронутые работы; разрешение продолжения имеет основание. История не стирается, старое подтверждение не перерисовывает более свежую геометрию.

Проверки предложены в RAW, но не выполнены этим ingest. Принятие: `FU-2026-10-13-001` и `FU-2026-10-13-002` в [[Vision_wiki/decisions/followups/index]].
