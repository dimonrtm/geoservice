# Отозвать переданный пакет до публикации

## Цель и участники

Остановить намерение публиковать точный пакет при неизменном содержимом, сохранив историю и достоверность исхода. Инициатор — назначенный Editor; координатор действует при отмене задания; владелец публикации определяет порядок/исход. Reviewer уведомляется, его четыре решения не расширяются.

## Основной поток

1. Установить packageId, цикл и полномочие; записать причину и ссылку на approval/snapshot.
2. Упорядочить принятие отзыва и допуск post-попытки по [[Wiki/policies/review_package_withdrawal_policy]].
3. Если отзыв первый — завершить пакет как withdrawn, запретить post, сохранить историю и уведомить Reviewer.
4. При новом намерении создать новый пакет с актуальными проверками и новым review, даже если содержимое совпало.

## Альтернативы

Post допущен первым: сохранить запрос, удержать новые попытки, установить долговечный outcome; доказанное окончание без эффекта → отзыв, успех → [[DDD_Wiki/use_cases/correct_published_result]]. Неизвестный исход не скрывать за timeout. Поздний эффект исполнителя должен быть исключён до вывода «без публикации».

Бывший Editor передаёт сообщение без обхода полномочий. Повторный отзыв возвращает тот же смысл результата. Отмена задания не делает автоматический Revert или reopen.

## Границы

Work Order предоставляет актуальное назначение, Review Post владеет решением по пакету, Audit сохраняет след. can_post — вычисляемая проверка, факт допуска конкретной попытки не переносится на следующую. Контракт реализации выбирается отдельно; first-save и серверные enum не меняются. Аналитические сценарии 1–10 находятся в RAW, это не выполненные тесты.
