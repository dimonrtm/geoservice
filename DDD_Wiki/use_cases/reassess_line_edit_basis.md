# Переоценить основание сохранённой правки

## Цель и триггер

Редактор/агент устанавливает, для каких утверждений сохранённый результат остаётся обоснованным после уточнения задания, изменения/отзыва источника, обнаружения зависимости копий, неизвестной даты или ошибки пояснения. Сценарий уточняет существующий workflow; нового bounded context не создаёт.

## Основной поток

1. Установить задачу, объект и сохранённое состояние. При неизвестном исходе сначала [[DDD_Wiki/use_cases/interrupted_edit_work_recovery]].
2. Сопоставить прежнюю и новую редакции основания; определить затронутые утверждения, область и зависимые заключения.
3. Проверить независимость/пригодность альтернативы, время наблюдения и критерий. Оценить [[Wiki/specifications/line_edit_basis_applicable]].
4. Зафиксировать эквивалентность либо новую оценку с фактической датой, причиной и ограничениями. История старого решения сохраняется.
5. При необходимости выполнить отдельную разрешённую коррекцию/возврат и current readback. Отсутствие нужды менять XY не отменяет записи нового обоснования.
6. Передать результат или открытый разбор с явным принятием следующей обязанности, отдельно от принятия правильности линии.

## Альтернативы

Альтернатива — копия отозванного наблюдения: независимость не доказана. Сменилось намерение на физическое изменение актива: отдельный объём вне текущего geometry-only среза. Ошибочна только последняя запись: выбрать обоснованное прежнее состояние для новой коррекции; не заменять baseline. Частичный результат зависит от незавершённой части: остаётся промежуточным draft. Выявлен дефект baseline: отдельный разрешённый процесс по существующей политике.

## Граница согласованности и реализации

EditVersion сохраняет существующие атомарные geometry guards и command idempotency; WorkOrder — существующее намерение и доступ. Revision внешнего документа, принятие свидетельства и Save не объявляются одной транзакцией. Новые события, repository, saga, command и автоматические статусы не вводятся.
