# Разобрать заявку на исправление карты

## Повод, участники и вход

Житель, мастер или смежная служба сообщает, что объект отсутствует на карте либо учтён неверно. Координатор учёта отвечает за разбор обращения до назначения наряда. Ему нужны исходное сообщение, ориентир или идентификатор, спорное свойство и способ дать ответ. Распорядитель данных подтверждает, кто ведёт это свойство. Получатели результата — заявитель и исполнитель следующего действия.

## Основной ход

1. Координатор сохраняет сообщение под номером и выделяет отдельные требования. Для каждого фиксирует, какую запись, место и дату имеет в виду заявитель.
2. Сверяет сведения с применимой редакцией карты и ранее открытыми делами. Совпадение адреса служит поводом сравнить предмет и обстоятельства.
3. Если требование уже выполнено, прикладывает ссылку на принятую редакцию. Если тот же дефект уже разбирают, связывает обращения. Для подтверждённого расхождения передаёт владельцу наряда предмет правки и основание. Когда требуется измерение, передаёт отдельное поручение на осмотр.
4. Сообщает заявителю решение по каждой части. Фиксирует согласованный способ ответа, сведения о доставке и владельца каждого остатка.

## Альтернативы и границы

- Если из сообщения нельзя установить объект или сторону улицы, координатор запрашивает конкретный ориентир. Остальные однозначные требования могут получить решение сразу.
- Если объединённые сообщения оказались о разных дефектах, координатор разъединяет их с сохранением ссылок и обязательств перед обоими заявителями.
- Разбор заканчивается, когда у каждого требования есть обоснованный ответ либо следующее поручение, принятое ответственным. Закрыть само обращение можно после выполнения условия ответа. Для персонального ответа проверяют доставку, для анонимного допустим результат по номеру согласно [политике обходов и обращений](../../Wiki/policies/inspection_work_policy.md).
- Сведения карты ведёт Utility Network. Work Order получает задание, когда оно действительно требуется. Проверку и публикацию исправления выполняют через [обычный цикл редактора](utility_editor_workflow.md).

## Условия завершения

По номеру обращения видно, кто и когда решил каждый пункт, из какой редакции это следует и кому передан следующий шаг. Координатор может завершить разбор при открытом осмотре. По карточке обращения остаётся видно, выполнено ли условие ответа заявителю.

## Проверка результата

О двух пропусках сообщили одним письмом. Первый объект уже виден в опубликованной редакции, для второго неизвестно, на каком вводе его увидел мастер. Заявитель получает ссылку по первому пункту и запрос ориентира по второму. Второй пункт остаётся открытым. Повторное письмо о нём связывают с тем же делом.

## Основание решения

В Eagle Pass службы сообщали картографам о пропусках. Порядок разбора дублей и уже внесённых изменений взят из процедуры PG&E. Обязанность по каждому требованию установила условная организация.
