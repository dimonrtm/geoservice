# Принять результат обследования и согласовать сведения сети

Полевой исполнитель вернул материал осмотра. Владелец наряда должен определить, что именно проверено, требуется ли изменение учёта и какие обязательства перед получателями остаются. Исполнитель, распорядитель данных, Reviewer и получатель могут принимать решения в разные дни.

| Шаг | Ответственный контекст | Решение |
| --- | --- | --- |
| Установить предмет | Utility Network | Определить владельца сведений о свойстве на дату и судьбу идентичности. Доказанный дубль даёт единую ссылку для новых поручений, а временная находка служит целью повторной идентификации. Для стыка двух фидеров нужно согласование обоих локальных концов. [[Wiki/concepts/data_stewardship_period]], [[Wiki/concepts/asset_identity_resolution]], [[Wiki/entities/feeder]]. |
| Соотнести наблюдение с местом и временем | Utility Network | Установить фактически построенную часть, прежнюю линейную привязку или оставленный в грунте фрагмент. Двусмысленность координаты удерживает вывод о точном месте, не уничтожая наблюдение. [[Wiki/concepts/linear_asset_lineage]], [[Wiki/concepts/asset_installation_history]]. |
| Принять результат задания | Work Order | Отчёт с подтверждённым охватом может закрыть самостоятельный осмотр при неизменной карте. Расхождение требует согласованного задания на правку. Выбранный порядок отсчёта определяет следующую дату обхода. Для каждого обращения отдельно сохраняется обязанность ответить. [[Wiki/policies/inspection_work_policy]]. |
| Проверить и опубликовать изменение | Review Post | Для требуемого изменения действуют прежние согласование версии, позиционная проверка и допуск. Проверить полномочие Reviewer в момент решения, текущие условия публикации и достаточность доступных свидетельств для каждого обязательного утверждения. [[Wiki/policies/reviewer_post_policy]], [[Wiki/specifications/post_allowed]]. |
| Довести результат до получателей | Ответственный за выпуск, Audit | Установить, что означают пропуски и коды поставщика. При ошибке выпущенной карты связать исходную и исправленную редакции с адресатами, временем выдачи и исходом уведомления. Аудит сохраняет основания решений. [[Wiki/policies/external_inventory_delivery_policy]], [[Wiki/concepts/dataset_delivery_edition]]. |

**Пример завершения.** Два обращения относятся к одному месту. Осмотр подтвердил сведения карты, отчёт принят, первый заявитель получил ответ, а для второго доставка не состоялась. Наряд на осмотр завершён. Вторая обязанность по ответу остаётся открытой. Создания пустого пакета публикации для такого результата не требуется.

**Граница применимости.** Геометрический Save защищают [[DDD_Wiki/invariants/edit_version_persisted_edit_invariants]]. Осмотр без правки не служит обходом проверки готовности изменённой линии к review. Внешняя дельта не изменяет локальный актив автоматически. Действующие технические проверки и очередь разработки — [[DDD_Wiki/model_health#Current Sprint Planning Queue]].
