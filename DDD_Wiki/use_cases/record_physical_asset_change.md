# Учесть физическое изменение сети и проверить открытый наряд

## Триггер и результат

Редактор получил свидетельство замены, ремонта, разделения или объединения. Есть либо может быть выданное ранее поручение на затронутый объект. Результат сценария — прослеживаемая запись факта и обоснованное решение по каждому затронутому поручению.

## Основной поток

1. Редактор устанавливает вид физической работы, дату действия и дату получения сведений. Сопоставляет материалы с экземпляром, позицией и границами участков.
2. Распорядитель сетевых данных квалифицирует изменение. Для установки проверяет предыдущий и новый периоды. Для преобразования линии устанавливает все пары происхождения и охват. [[Wiki/concepts/asset_installation_history]], [[Wiki/concepts/linear_asset_lineage]].
3. Владелец наряда сверяет исходную цель, тип адресата и правило выбора времени с установленным фактом. Фиксирует фактически обследованный объект, решает судьбу остатка. [[Wiki/policies/work_order_target_after_asset_change]].
4. Редактор готовит изменения данных в разрешённом рабочем контексте. Проверяющий различает предметную применимость, сетевую проверку и согласование публикации. Для результатов, опубликованных до уточнения, действует [[Wiki/policies/published_result_correction_policy]].

## Исключения и границы

Неоднозначная маркировка допускает запись наблюдения с неизвестным экземпляром. Два исходных участка требуют двух проверяемых связей. Картографическое разбиение порождает новую редакцию представления. Недоступный актив оставляет открытой обязанность по наряду до принятого решения о её судьбе.

Utility Network владеет сведениями о сети и соответствиях. Work Order владеет целью и разрешённым объёмом. Review Post отвечает за пакет и публикацию. Это сценарий модели условной организации.
