# AR-02 · План реализации

Для исполнения по шагам использовать `superpowers:executing-plans` или, при выборе делегирования, `superpowers:subagent-driven-development`.

**Цель.** Завершать запись и доставлять уведомление быстрому подписчику при заблокированной отправке другому подписчику. Открытая карта сохраняет актуальную версию и автоматически восстанавливается после разрыва.

**Архитектура.** FastAPI ставит сериализованное событие в отдельную ограниченную FIFO каждого сокета после выхода из транзакции. Vue применяет версии к единому кешу слоя. При восстановлении подписки наполняет новое поколение кеша из PostGIS через существующие HTTP-маршруты. [Принятый дизайн](2026-11-02-ar-02-design.md)

**Ограничения.** Один процесс, включённый legacy GIS, существующие гарантии AR-01 и BE-03. Начальные параметры для реализации — 32 ожидающих кадра, 5 секунд на отправку и **1 МиБ ожидающих данных на сокет**. Последнее значение выбрано в плане как бюджет памяти, измеряемый по UTF-8 фактически передаваемого JSON. Оно допускает один обычный крупный кадр либо несколько малых. Кадр в работе учитывается отдельно, его размер также ограничен 1 МиБ. Размер HTTP-записи этим бюджетом не ограничивается. Каждый параметр подменяем в тестах. Изменения оставлять unstaged.

**Особое внимание при ревью.** Первый кадр при одновременной публикации и connect (шаг 1), многобайтовые символы на границе бюджета (1), поздняя публикация после смены поколения (3), поздняя страница при перемещении объекта (3), временная ошибка HTTP при уже восстановленном сокете (4).

Команды Python ниже выполнять из `apps/backend`, команды npm из `apps/frontend`. Для каждого шага сначала воспроизвести нарушение новым тестом, затем реализовать изменение и повторить тест.

Результаты исполнения и границы проверки приведены в [отчёте приёмки](evidence/ar-02/verification.md).
