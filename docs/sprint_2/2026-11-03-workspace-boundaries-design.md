# Раздельное чтение данных редактора

Спецификация принята пользователем 03.11.2026. [Анализ модели, кода и требований](2026-11-03-workspace-boundaries-analysis.md) · [План реализации](2026-11-03-workspace-boundaries-plan.md)

## Граница модели

Workspace обозначает экран редактора. Серверный агрегат `WorkspaceAggregateRow`, межсхемная выборка `workspace_aggregate.sql` и прежний публичный `GET .../workspace` подлежат удалению. Названия компонентов интерфейса могут отражать назначение экрана.

Один репозиторий читает данные только своего ограниченного контекста. Сервис может использовать два репозитория в одном сценарии. Это правило распространяется и на Save, где сегодня `edit_geometry_context.sql` соединяет таблицы двух контекстов. Разделение запросов сохраняет атомарность команды, проверку доступа, блокировку версии, проверку токена, идемпотентность и правила отката.

## Контракты чтения

| Чтение | Данные и гарантии |
| --- | --- |
| Наряд с рабочей версией | Из `work_order` приходят WorkOrder, AOI, EditVersion, текущие объекты карты, связи и `draftVersionToken` того же снимка. Карта показывает объекты, пересекающие AOI, и связи с двумя видимыми концами. Этот ответ достаточен для просмотра. |
| ChangeSet версии | Сервис читает текущие данные из `work_order` и исходные из `utility_network` через разные репозитории. Исходный снимок определяется ссылкой открытой версии. Сервис сравнивает геометрию по всей версии, включая объекты за пределами выборки карты, и сохраняет проверки согласованности текущей проекции. Ответ содержит токен прочитанной рабочей ревизии, состояние проверки и пустой ChangeSet либо сведения об изменённой фиче, операции и индексе вершины. Недоступность baseline означает ошибку чтения. |
| Baseline одной фичи | После проверки доступа к наряду, версии и фиче сервис получает исходную геометрию из `utility_network` по идентификаторам закреплённого снимка и фичи. Именно этот HTTP-ответ передаёт исходную геометрию клиенту. |

## Модули фронтенда

В `stores/workOrders.ts` остаются список назначенных нарядов, выбор наряда, его статус и состояние загрузки списка. Три чтения редактора имеют собственные контракты, API и состояния загрузки. Координация открытия, восстановления экрана и согласования токенов относится к редактору. Карта получает текущее состояние рабочей версии независимо от состояния локальной правки.

Локальный черновик и действия с вершиной, команды Save и отката, навигация с подтверждениями получают отдельных владельцев состояния. Save и откат используют существующий механизм восстановления команд. Компоненты и обработчики сессии обращаются к модулям по назначению. Хранилище нарядов не проксирует команды редактора.

## Сценарии редактора

1. После успешного чтения наряда и версии экран показывает карту в режиме просмотра и запрашивает ChangeSet. Если токены двух ответов различаются, клиент автоматически перечитывает оба ответа. Результаты прежнего запроса не должны применяться после смены наряда, версии или пользователя.
2. При согласованных токенах и пустом ChangeSet редактор выбирает линию на карте. Клиент загружает baseline этой линии. При непустом ChangeSet клиент сразу запрашивает baseline указанной фичи. После успешной загрузки становятся доступны допустимые для линии действия, включая откат сохранённой правки.
3. При временной недоступности данных карта остаётся в режиме просмотра. Для ChangeSet и HTTP-запроса baseline действуют независимые циклы: первая попытка сразу, затем до четырёх повторов с паузами 2, 5, 10 и 20 секунд. После пятой неудачи экран показывает «Повторить». Кнопка запускает новый цикл только для чтения, которое завершилось ошибкой. При смене выбранной линии ответ за прежнюю линию не разрешает редактирование новой.
4. После Save, отката или восстановления соединения актуальная геометрия и состояние изменений берутся из readback. Повтор ранее исполненной команды может вернуть исторический результат. Он не должен заменять более новую геометрию карты.

## Приёмочные проверки

- Загрузка и выбор наряда работают независимо от модулей редактирования. Локальная правка, Save и откат, уход с несохранённым черновиком и выход из сессии покрыты проверками через новые точки входа. После смены пользователя прежний запрос не изменяет экран.

- Загрузка первого ответа и просмотр карты возможны при недоступном baseline. Ошибка ChangeSet визуально отличается от успешно прочитанного пустого результата.
- На чистой версии baseline запрашивается для выбранной линии. Для сохранённой правки экран автоматически загружает исходную линию и позволяет запустить откат без повторного выбора.
- При сохранении из другой сессии между запросами экран обнаруживает разные токены, перечитывает данные и допускает редактирование только после согласования версии и загрузки нужной линии.
- Для каждого из двух зависимых чтений проверяются успех на повторе, пять неудач и ручной перезапуск. Ошибка загрузки одной линии не сбрасывает успешно прочитанный ChangeSet.
- При удалении старого маршрута обновлены клиент, проверки HTTP и сквозные сценарии открытия, Save, отката и восстановления. Репозитории каждого контекста обращаются только к собственной схеме.
