# FE-03 — безопасная отрисовка workspace при загрузке карты

Дата: 2026-10-31. Статус: принят пользователем («Принимаю»). Размер: небольшое исправление двух frontend-модулей с проверками их взаимодействия.

Основания: [анализ и согласование границ](2026-10-31-fe-03-workspace-style-readiness-analysis.md), [исходное ревью](frontend-review.md), [принятый дизайн FE-02](2026-10-31-fe-02-map-initialization-design.md).

## Цель и согласованные границы

Асинхронное обновление workspace во время первоначальной загрузки карты не вызывает запись источников и слоёв в неготовый стиль. После загрузки отображается актуальное состояние из props. После уничтожения карты её API не вызывается ни из MapView, ни из отложенных действий useMapInstance; эту сквозную гарантию пользователь подтвердил отдельно.

Готовность команд сохраняет смысл FE-02: успешная первоначальная отрисовка workspace завершена. Store остаётся владельцем current, local draft и recovery. Исправление не меняет API, доменные guards, baseline, CommandId и правила восстановления.

## Подходы

**Выбран пользователем: локальное исправление существующего порядка.** Watcher обновляет подготовленную карту; первый render остаётся после успешного createMap и читает последние props. useMapInstance прекращает незавершённую инициализацию при удалении экземпляра. Преимущество — сохранение структуры FE-02 и небольшой объём изменения; обязательство — проверить оба асинхронных пути, компонент и composable.

**Рассмотрен: отдельное реактивное состояние готовности стиля в composable.** Позволяет объединить отрисовки вокруг общего сигнала и полезно при нескольких потребителях или переключении стилей. Сейчас создаёт дополнительное состояние, которое нужно согласовывать с готовностью workspace и команд; пользователь выбрал первый подход.

## Поведение и технические решения

Детали ниже — решения автора дизайна в рамках выбранного подхода, а не отдельные ответы пользователя.

1. Пока createMap ожидает load, изменения props не вызывают ensureWorkspaceLayers, setWorkspaceData, fitWorkspaceToAoi или workspaceFitted. Очередь промежуточных snapshots не создаётся: актуальные данные уже находятся в props.
2. После успешного createMap живой MapView выполняет первоначальный render по текущим props; только затем сообщает ready=true. Нельзя блокировать этот первоначальный render условием mapReady, поскольку ready устанавливается после него. Ограничение готовностью применяется к пути watcher. Синхронная ошибка первичного render сохраняет обработку FE-02: сообщение ошибки и отсутствие готовности команд.
3. После готовности обычные обновления workspace продолжают отображаться. Сохраняются текущие shouldFitWorkspace/workspaceKey и подтверждение workspaceFitted после фактического fit. Readback того же контекста не получает нового принудительного fit. Изменение shouldFitWorkspace после подтверждения может вызвать существующий дополнительный render; требование не означает глобальный запрет всех повторных setData.
4. useMapInstance связывает ожидание и callback load с конкретным экземпляром/запуском. Подписка должна быть установлена до асинхронного промежутка, в котором событие можно пропустить. После каждого nextTick и перед последующим вызовом Map API проверяется, что запуск ещё действителен. Позднее продолжение старого запуска не действует на новый экземпляр.
5. destroyMap сначала инвалидирует запуск и снимает ожидающий обработчик load, затем удаляет экземпляр и очищает ссылку. Незавершённый createMap завершается с null как отменённый запуск, без ожидания будущего load. Уже начатый callback также проверяет отмену после своего await. Повторное destroyMap безопасно; один экземпляр удаляется не более одного раза. Вызовы очистки до remove допустимы; после remove вызовов API этого экземпляра нет.
6. MapView сохраняет проверку disposed сразу после await createMap, до обработки null. Поэтому штатный уход не показывает ошибку запуска и не публикует позднюю готовность. Ошибки действующего запуска сохраняют существующую обработку FE-02.

## Вне задачи и недопустимые последствия

Не вводятся timeout загрузки, общий обработчик всех MapLibre error events, восстановление после runtime WebGL failure, переключение стилей, новые индикаторы или кнопки retry. Безопасная отмена при destroy входит в FE-03, хотя была исключена из FE-02.

Недопустимы преждевременное ready=true, потеря последнего workspace, отметка fit до готовности, вызовы уничтоженной карты, очистка recovery/draft ради renderer или создание новых mutation-запросов. Произвольные переключения legacy editing в workspace на одном экземпляре не становятся новым продуктовым сценарием этого исправления.

## Приёмка

| Сценарий | Ожидаемый результат |
| --- | --- |
| Map уже создан, load задержан, workspace несколько раз заменён | До load нет workspace-записей/fit/ready=true; первая отрисовка после загрузки использует последний workspace и текущий key |
| Во время ожидания изменены shouldFitWorkspace и контекст | После загрузки учитываются текущие props; устаревший key не помечается fitted |
| Readback после готовности | Новые данные отображаются; сохраняется прежнее условие fit и доменное состояние |
| Ошибка первичного render | Существующее сообщение FE-02, команды скрыты |
| Удаление до первого nextTick | Нет последующего resize или регистрации отложенной работы с удалённой картой; createMap завершается |
| Удаление во время ожидания load | Обработчик снят, Promise завершён, remove выполнен один раз; поздний callback не обращается к API |
| load получен, удаление произошло во время nextTick его обработчика | Нет позднего resize, render или ready=true |
| Удаление после resolve, до продолжения MapView | disposed блокирует отрисовку и публикацию готовности |
| Обычный запуск empty/editing/workspace и повторная очистка | Существующее поведение FE-02 сохраняется; очистка безопасна |

Нужны компонентные тесты с управляемым createMap и отдельные тесты настоящего useMapInstance с подменённым MapLibre Map и управляемыми событиями. Компонентные mocks не доказывают внутреннюю отмену composable. В плане предусмотреть релевантные regression tests и typecheck; браузерную проверку реального MapLibre отделять от unit evidence и не объявлять выполненной по результатам mocks.
