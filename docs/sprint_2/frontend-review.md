Подтверждены три дефекта P2 и один P3. P1 в проверенных frontend-сценариях не установлен. Подтверждение здесь означает прослеживаемый путь исполнения или непосредственное противоречие в разметке; реальный браузер, WebGL и screen reader в этом ревью не запускались. Прочитаны `AGENTS.md`, memory protocol/file-map, релевантное решение о ролях, требования Sprint 2 и согласованные границы Дня 11. Reviewer review/post — будущий scope, а не дефект. ## FE-01 · P2 · Повтор восстановления сессии открывает конкурентный login и допускает устаревший ответ

**Код:** `apps/frontend/src/stores/auth.ts:155–179`, особенно :157–162 и :172; `apps/frontend/src/App.vue:53–62,119–120`; новый login устанавливает сессию в `auth.ts:147–153`.

**Сценарий:** первоначальный refresh завершается 503/timeout. Store выставляет `isReady=true`, `sessionError` и пустого пользователя. Нажатие «Повторить» вызывает `restoreSession()`, который очищает ошибку, но не меняет `isReady`. App проверяет только `!auth.isReady`, поэтому во время refresh показывает работающую форму входа. Пользователь входит, пока старый refresh ещё ожидает ответа. Поздний успех refresh без проверки epoch вызывает `setAuth` для прежнего пользователя; поздняя ошибка вызывает `clearLocalSession` и сбрасывает новый вход. Даже защита старых 401 в HTTP interceptor не предотвращает безусловный catch самого `restoreSession`.

**Последствия:** неожиданное завершение новой сессии или переключение пользователя и рабочего контекста. Это гонка одной вкладки; межвкладочная ротация refresh cookie — отдельный вопрос.

**Рекомендация:** показывать восстановление при `isRestoring`, исключить конкурентные auth-действия и проверять generation/sessionEpoch перед каждым применением результата, ошибкой и finally. Одного скрытия формы недостаточно для корректности store.

**Проверка исправления:** deferred refresh → retry screen → запрет login во время restore; отдельно deferred refresh → новая сессия → поздние success/503/401 не изменяют нового actor и readiness. Существующий `auth.epoch.test.ts` проверяет interceptor-подобный unauthorized путь, но не этот restore continuation.

## FE-02 · P2 · Ошибка создания карты невидима в основном workspace

**Код:** `apps/frontend/src/components/MapView.vue:20–22,223–224`; ожидание карты — `apps/frontend/src/composables/map/useMapInstance.ts:16–37`.

**Сценарий:** пользователь успешно открывает workspace, но `new Map`/создание WebGL-контекста выбрасывает исключение. Catch пишет «Не удалось инициализировать карту» в `labelText`. Единственный элемент, отображающий `labelText`, исключён условием `mode !== 'workspace'`.

**Последствия:** пустая рабочая карта без объяснения, команды предлагают выбрать линию, пользователь не получает понятного пути восстановления. Ошибки асинхронной загрузки также не превращаются в отклонённый `createMap`: Promise слушает только `load`, без error/timeout/cancel. Последнее — дополнительный риск жизненного цикла, не доказательство того, что любой отказ raster tile блокирует `load`.

**Рекомендация:** отдельное реактивное состояние инициализации карты, видимое во всех режимах, с доступным сообщением ошибки и retry; отдельно определить отказ/отмену ожидания MapLibre load.

**Проверка исправления:** mocked rejection `createMap` в workspace должен показать alert и повтор; проверить отказ WebGL в реальном браузере и unmount до load. Текущий `MapView.test.ts` проверяет отсутствие badge в успешном workspace, но не ошибку.

## FE-03 · P2 · Workspace watcher пишет слои до готовности стиля

**Код:** `apps/frontend/src/components/MapView.vue:178–184,228–234`; `apps/frontend/src/composables/map/useMapInstance.ts:24–35`; `apps/frontend/src/map/workspace-layers.ts:25–37`.

**Сценарий:** Map instance уже помещён в `map.value`, но `load` ещё не пришёл; в этот промежуток recovery/readback заменяет `props.workspace`. Watcher сразу вызывает `renderWorkspace()`. Проверяется наличие map/workspace, но не `mapReady` или `isStyleLoaded`. `ensureWorkspaceLayers` вызывает `addSource` у неготового стиля.

**Подтверждение:** установленный MapLibre вызывает `_checkLoaded()` в `Style.addSource` (`node_modules/maplibre-gl/src/style/style.ts:1000–1001`), а проверка выбрасывает `Style is not done loading` (:707–709). Watcher находится вне try/catch обработчика onMounted.

**Последствия:** необработанная ошибка Vue watcher при штатном изменении асинхронных данных. Последующий load может восстановить отображение, поэтому постоянная потеря карты не заявляется.

**Рекомендация:** до готовности карты только сохранять актуальные props; после load единожды отрисовывать последнюю версию. Защитить continuation от unmount; не трактовать наличие Map object как готовность стиля.

**Проверка исправления:** deferred createMap/load → замена workspace несколько раз → ни одного addSource до load → после load отображается только последний workspace; unmount до resolve не вызывает API уничтоженной карты.

## FE-04 · P3 · Русский интерфейс объявлен англоязычным документом

**Код:** `apps/frontend/index.html:2` (`lang="en"`); название вкладки :7 — `frontend`.

**Сценарий и последствия:** screen reader выбирает английские правила произношения для русского интерфейса; название вкладки не помогает отличить приложение. Неверный язык подтверждён разметкой; реальное произношение конкретного screen reader не проверялось.

**Рекомендация:** `lang="ru"`, осмысленный title GeoService; проверить язык документа и название вкладки компонентной/HTML-проверкой, затем screen reader smoke.

## Производительность и code smells — отдельно от доказанных пользовательских сбоев

- `useWorkspaceLineInteraction.ts:72–105,269–279` обновляет draft на каждом drag и вызывает `setWorkspaceDraftData`; `workspace-layers.ts:180–196` каждый раз собирает все объекты workspace, синхронно сериализует и разбирает весь GeoJSON, затем отправляет его в worker. Работа и аллокации растут с полным размером workspace, хотя меняется одна вершина. Это подтверждённая избыточная работа, **P3 / кандидат оптимизации**, но задержка на принятом demo-наборе не измерялась. Сначала снять профиль с большим workspace; затем отделить редактируемую геометрию в overlay/source и ограничить обновления animation frame.
- `stores/workOrders.ts` совмещает выбор наряда, storage markers, навигацию, локальную геометрию, recovery coordination, read generations, сравнение и представление состояния. Это увеличивает число зависимых инвариантов при правках. Разделять по контрактам ответственности после фиксации regression tests; переписывание ради размера файла не требуется.
- Legacy generic editing/realtime присутствует в MapView, но текущий App использует utility workspace. Ошибки только legacy-пути нельзя автоматически объявлять блокерами пользовательского сценария Sprint 2.

## Что проверено по безопасности и устойчивости

Текстовые данные выводятся интерполяцией Vue; в просмотренных компонентах не найдено пути HTML injection через `v-html`. Access token находится в памяти auth store; HTTP request получает epoch, а поздний unauthorized ответ прежней epoch отсекается. UI роли не являются заменой серверной авторизации. Recovery механизмы имеют actor/context gating; это положительные наблюдения, а не сертификат безопасности. Browser storage, cookie policy и серверные границы доступа требуют совместного backend-ревью.
