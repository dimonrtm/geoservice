# День 11 — отчёт реализации команд пользователя

Дата: 2026-10-18. Основание: [принятая спецификация](2026-10-18-day-11-user-commands-design.md), [план](2026-10-18-day-11-user-commands-plan.md). Пользователь поручил реализацию. Код реализован и проверен; настоящий browser zoom 200% остаётся непроверенным, ниже приведена граница responsive evidence.

## Реализованное поведение

- Панель над картой: «Сохранить», «Отменить», «Сбросить», выбранная линия, сообщения операции и отдельное русское пояснение непроверенной позиционной точности.
- Save сразу отправляет правку. Store удерживает identity до первого await; повторное действие не создаёт второй запрос. После успеха и readback выбор снят, маркер отсутствует.
- Cancel без диалога и HTTP возвращает current, сохраняя выбор и маркер. Отмена через клик по карте сохраняет прежний диалог.
- «Сбросить» доступна при persisted changeSet вне блокировок и только сообщает о недоступности функции. Геометрия не меняется.
- Unknown, stale, storage/access/protocol failures и успех с ошибкой readback имеют разные сообщения и соответствующие блокировки. Ручного recovery UI нет.
- No-op выводится только при наличии исходного current той же отправки; восстановленная квитанция без него не получает недоказанную классификацию.
- Нативный modal dialog блокирует фон, поддерживает Tab/Shift+Tab и Escape, корректно возвращает фокус. Кнопки имеют видимый фокус, статусы — live region. Само перемещение вершины с клавиатуры не добавлялось.

## Затронутые области

`WorkspaceEditCommands.vue` представляет панель; `workspaceCommandPresentation.ts` вычисляет разрешения и сообщения. `EditorWorkOrdersView.vue` размещает панель, допускает прокрутку рабочей области и сохраняет минимальную высоту карты. `workOrders.ts` добавляет атомарный Cancel с сохранением выбора и неперсистентные evidence для no-op/отклонённой candidate. Карта блокирует взаимодействие также при storage failure. Backend, API, migrations, dependency manifests и формат sessionStorage не изменены.

## Независимое review

Read-only review `day11_review` проверило весь unstaged frontend diff и новые файлы, не меняло код и не запускало тяжёлые тесты.

Исправлены с RED→GREEN:

1. После отказа candidate A, движения в B и возврата в A Save был заблокирован без объяснения. Теперь снова отображается причина серверного отказа.
2. Возможная потеря фокуса после подтверждённой отмены на карте воспроизведена в реальном браузере: activeElement становился BODY. Теперь modal закрывается до удаления, восстановление фокуса ждёт обновления DOM. Повторная browser-проверка дала CANVAS, доступный инициатор.

Незначительное замечание исправлено по следующему поручению пользователя: сообщение о недоступности Revert очищается после нового движения вершины или выбора линии. Два новых component tests с реальным Pinia воспроизвели ошибку до изменения и прошли после него; основной dirty-статус и геометрия сохраняются, дополнительных HTTP нет.

## Browser demo

Локальный frontend-dev пересобран и обновлён через compose `up -d --no-deps --build frontend-dev`. Backend и PostGIS не пересоздавались, volumes не удалялись.

В `http://localhost:5173` под demo Editor выполнены:

1. Открытие WO-001: 19 объектов, 9 связей; панель располагается над картой.
2. Выбор L-003 и движение внутренней вершины. Save/Cancel становятся доступными.
3. Cancel через Space: нет диалога, геометрия возвращается, выбор/маркер остаются; focus на heading панели.
4. Dirty → клик по пустому месту: modal, безопасный начальный фокус, Shift+Tab циклически переводит на подтверждение; Enter подтверждает отмену и возвращает focus на карту. AX дерево modal содержит только диалог.
5. Новое движение → Save через Enter: сохранение, актуальная карта, выбор/маркер сняты. «Сбросить» через Space показывает недоступность без сброса.
6. Reload страницы: новая геометрия сохранена. Затем новое движение и Cancel возвращают именно сохранённый current, не первоначальный baseline.
7. Escape из диалога оставляет dirty candidate; заключительный Cancel отменяет эту локальную попытку.

Состояние demo после проверки: **L-003 имеет сохранённое изменение в рабочей версии; несохранённой правки нет, линия остаётся выбранной с маркером после Cancel**. Изменение не сбрасывалось скрытой API-командой: Revert UI остаётся задачей Дня 12.

Основной demo не содержит нескольких eligible lines в одной точке; переход из списка неоднозначного выбора проверен component test, не объявлен отдельной ручной проверкой. Реальные network failures искусственно не создавались; эти ветви проверены автоматическими fixtures.

## Responsive evidence и ограничение zoom

Проверены реальные viewport 1440×900, 1024×768 и 768×1024. Панель и кнопки доступны, текст переносится, карта не перекрывается, рабочая область прокручивается.

Встроенный браузер не применил Ctrl+Plus: `devicePixelRatio` и `innerWidth` не изменились. Поэтому вместо ложного заявления о настоящем 200% zoom дополнительно проверена компоновка на эквивалентных CSS viewport 720×450, 512×384 и 384×512. Кнопки доступны клавиатурой и прокруткой, на 384px переносятся на вторую строку; горизонтального overflow документа не обнаружено. **Это проверка reflow, а не полноценная проверка browser zoom 200%; последний пункт остаётся для обычного браузера.** Временный viewport override снят.

## Решения исполнения и ограничения

- Использован существующий checkout ветки `first-edit-save`: последовательная работа уже авторизована пользователем; новый worktree не создавался. Цена — изменения находятся в общей рабочей копии и требуют пользовательского review перед staging.
- Ledger сохранён в `docs/sprint_2/`, а commit-oriented helpers skills заменены прямыми проверками из-за AGENTS.md. Цена — история выполнения хранится в документах, не в серии коммитов.
- Revert execution, ручной recovery, stale resolution, новые navigation/relogin сценарии, keyboard geometry, смартфоны и backend/storage format оставлены вне scope по принятой спецификации. Цена — эти продолжения пользовательского сценария ещё недоступны.

Git add/commit/push не выполнялись; результат оставлен unstaged. Отдельная agent memory и repository-change ingest не создавались: принятые решения и связи уже сохранены в спецификации, коде и этом отчёте.
