# AR-01: восстановление сессии в dev блокировалось CORS

## Причина

Frontend на `http://localhost:5173` обращается к backend на
`http://localhost:8000`: это разные origin. После появления маркера сессии
refresh отправляет `X-Expected-Session-Id`. В `web_api/main.py` этот заголовок
отсутствовал в `CORSMiddleware.allow_headers`.

В логах dev наблюдались успешные login (200), затем повторные OPTIONS refresh
(400). Контрольный OPTIONS с Origin и Access-Control-Request-Headers подтвердил
ответ `Disallowed CORS headers`. Браузер блокировал основной запрос и представлял
ошибку приложению как сетевую; UI предлагал повторить восстановление.

Предыдущие проверки на одном origin не проверяли эту границу dev-развёртывания.

## Исправление и проверка

- В разрешённые заголовки добавлен `X-Expected-Session-Id`.
- Новый `test_auth_cors.py` проверяет preflight на настоящем middleware приложения,
  разрешённый origin, credentials и разрешение нового заголовка.
- До исправления тест падал: ожидался 200, получен 400. После исправления
  26 тестов CORS, auth API, correlation middleware и edit contract прошли.
- Пересобран и перезапущен только локальный dev-сервис `utility_service`.
- Тот же OPTIONS к работающему dev после исправления возвращает 200 OK
  и разрешает новый заголовок.

Вход с учётными данными пользователя автоматически не выполнялся. На открытой
странице следует нажать «Повторить» или обновить страницу. Если старая сессия
завершена миграцией, ожидается форма повторного входа.
