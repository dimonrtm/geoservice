# План разделения чтения данных редактора

Основание — [принятая спецификация](2026-11-03-workspace-boundaries-design.md). Реализован и проверен 04.11.2026. [Результаты проверок](2026-11-04-workspace-boundaries-report.md).

Цель — дать редактору карту независимо от доступности baseline и убрать серверный агрегат Workspace. Стек — FastAPI, SQLAlchemy, PostgreSQL/PostGIS, Vue и Pinia. Шаги предназначены для последовательного выполнения с `superpowers:executing-plans` либо по задачам с `superpowers:subagent-driven-development`. Команды Python ниже выполняются из `apps/backend`, npm — из `apps/frontend`. Для интеграционных проверок нужна тестовая БД с миграциями PostGIS.

## Границы и точки проверки

Каждый репозиторий работает только со своей схемой. Для сравнения используется снимок, закреплённый за открытой версией. Сохраняются действующие права доступа и правила Save, повторов команд и отката. При ревью проверить скрытое изменение за пределами AOI, неверную принадлежность baseline, расхождение токенов, поздний ответ после смены пользователя или линии и исчерпание попыток только одного из двух чтений.
