# BE-02: план реализации

> **Для исполнителя:** применять `superpowers:executing-plans` при самостоятельной реализации либо `superpowers:subagent-driven-development`, если пользователь выберет работу через агентов. Шаги отмечать по фактическому выполнению.

**Цель:** корректно очищать properties в legacy PATCH без ошибочного ответа или отката.

**Архитектура:** локальное исправление выбора properties при сборке `FeatureOut`. Существующие repository, транзакция и публикация после commit сохраняются.

**Технологии:** Python, Pydantic, SQLAlchemy AsyncSession, FastAPI, pytest, PostgreSQL/PostGIS, Docker Compose.

**Дизайн:** [2026-11-01-be-02-design.md](2026-11-01-be-02-design.md), принят пользователем. Основания: [анализ](2026-11-01-be-02-analysis.md).

## Общие ограничения

- `geometry` и `properties` обязательны; `null` сохраняет прежнее значение, `{}` очищает properties. Оба `null` недопустимы.
- SQL, repository-контракт, optimistic locking, legacy no-op/version semantics, доступ и Utility Save не меняются.
- Только disposable test-БД; demo-БД не использовать. Test isolation guard не обходить.
- Product code не получает hooks для тестовых ошибок; сбой внедряется тестовой подменой.
- Артефакты — в `docs/sprint_2`; текст UTF-8 с LF. Не выполнять `git add`, `git commit`, `git push`.

## Фокус проверки

- Уже пустые properties: повторная очистка успешна и повышает legacy version — задача 1.
- Непустой объект с `false`, `0`, `null`: значения сохраняются — задача 1.
- Пропуск поля отличается от явного `null`: обязательность сохранена — задача 1.
- Stale version при очистке: нет записи и события — задачи 1–2.
- Ошибка после выполненного UPDATE до commit: полный rollback, нет события — задача 2.
