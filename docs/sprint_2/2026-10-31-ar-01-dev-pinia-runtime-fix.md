# AR-01: пустой список нарядов в dev из-за identity Pinia actions

## Подтверждённая причина

После входа редактора UI показывал «Назначенных нарядов нет», workspace не
загружался. Read-only проверка dev-БД подтвердила наличие `WO-001` в состоянии
`in_progress`, назначенного demo-редактору, и одной `EditVersion`. В логах
наблюдались успешные status-запросы, но отсутствовал запрос списка нарядов.

`auth.ts` хранил Runtime в `WeakMap`, используя `this` store как ключ. В dev
Pinia `patchActionForGrouping` создаёт отдельный Proxy store для вызова каждого
action. Поэтому `startBrowserSessionSync`, `restartSessionMonitor` и
`ensureSessionReady` получали разные Runtime. Проверка готовности не находила
monitor и возвращала false; HTTP interceptor отменял запрос до отправки.
Отмена не отображалась как ошибка, и пустое начальное состояние списка выглядело
как отсутствие назначений.

Обычный test-режим Pinia отключает devtools-плагин, поэтому прежние unit-тесты
этого поведения не воспроизводили. Production-сборка также не включала эту
dev-обёртку.

## Исправление

Перед доступом к WeakMap ключ нормализуется через `toRaw(store)`. Разные
обёртки действий одного store используют общий Runtime; отдельные store
сохраняют изоляцию.

Добавлен тест `shares_session_runtime_across_devtools_action_proxies`:
Pinia установлена в Vue app, NODE_ENV временно переключён на development для
включения настоящего devtools-плагина. До исправления ожидание ready=true
падало с false; после исправления прошло.

## Проверка в dev

- Пересобран только `frontend-dev`; назначения и геометрия не менялись.
- В отдельном Chrome-контексте выполнен вход demo-редактора.
- Список нарядов: HTTP 200, `WO-001` виден.
- Открытие существующего workspace: HTTP 200, панель данных видна.
- После reload список и workspace восстановились.
- Проверка TypeScript прошла; 68 целевых frontend-тестов прошли.
- Полный frontend-прогон: 439 тестов в 52 файлах прошли; ESLint изменённых
  файлов и `git diff --check` прошли. Файлы записаны с LF.

Первый браузерный прогон после reload остановился из-за неоднозначного
селектора кода наряда (код виден и в списке, и в workspace). После ограничения
селектора кнопкой списка полный сценарий прошёл.

Для уже открытой пользовательской вкладки требуется обновление страницы,
чтобы сбросить runtime старой версии.
