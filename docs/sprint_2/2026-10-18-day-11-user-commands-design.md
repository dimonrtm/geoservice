## 2. Объём

В День 11 входят:

- панель над картой с командами «Сохранить», «Отменить», «Сбросить»;
- рабочие Save и Cancel, а для Revert — только сообщение о недоступности;
- отображение local dirty, этапов сохранения, результатов, отказов и блокировок;
- защита от повторной отправки через UI и существующий store;
- клавиатурная доступность кнопок и диалогов;
- component/view tests и responsive review для компьютера и планшета.

Не входят: выполнение Revert, ручные retry/readback/recovery actions, разрешение stale через UI, новые сценарии навигации и relogin, клавиатурный выбор линии и перемещение вершины, смартфонная приёмка, backend/API/migrations и новые dependencies. Автоматический recovery Дня 9 сохраняется.

## 3. Панель и тексты

Новый `WorkspaceEditCommands.vue` размещается в `EditorWorkOrdersView.vue` над картой внутри открытого workspace. Панель занимает место в потоке и не перекрывает карту. Она показывает выбранную линию, кнопки, состояние операции и отдельное пояснение качества. Закрытый/недоступный workspace не показывает приватный контекст редактирования.

Подписи: Save — **«Сохранить»**, Cancel — **«Отменить»**, Revert — **«Сбросить»**. Пояснение Revert: «Вернуть линию к исходному состоянию». Короткую подпись дополняет доступное объяснение назначения.

| Ситуация | Сообщение |
| --- | --- |
| Нет local dirty | «Нет несохранённых изменений» |
| Есть local dirty | «Есть несохранённые изменения» |
| PUT выполняется | «Сохраняем правку…» |
| Ожидание автоматического повтора | «Ожидаем повторной попытки сохранения…» |
| Подтверждён успех, идёт GET | «Правка сохранена. Загружаем актуальные данные…» |
| Успех и current получен | «Правка сохранена в рабочей версии» |
| Доказанный no-op | «Сохранение выполнено без новых изменений» |
| Unknown после исчерпания повторов | «Не удалось узнать, сохранена ли правка. Редактирование временно недоступно» |
| Успех PUT, ошибка GET | «Правка сохранена, но актуальные данные карты не удалось загрузить. Редактирование временно недоступно» |
| Stale | «Данные изменились после начала вашей правки. Она не сохранена. Редактирование временно недоступно» |
| Нажатие «Сбросить» | «Возврат к исходному состоянию пока недоступен» |

Для чтения после stale нельзя использовать сообщение «Правка сохранена»: текст определяется известным результатом команды, а не только `phase=reading-current`. При ошибке этого чтения сообщается об отклонённой правке и невозможности загрузить актуальные данные.

Известные validation/access/storage/protocol errors получают русские объяснения по фактическому состоянию. Неизвестный код не выводится как основной пользовательский текст. Сбой сохранения recovery record до PUT не объявляется неизвестным исходом отправки: отправки ещё не было. Нельзя советовать кнопку восстановления, отсутствующую в Дне 11.

Progress передаётся этапом и индикатором ожидания, без выдуманного процента. Ошибка чтения не продолжает изображаться бесконечной загрузкой. Сообщение Revert не заменяет основной статус или ошибку; оно не модальное и не меняет local draft.

Отдельное пояснение в открытой рабочей области: **«Позиционная точность не проверена. Сохранение не подтверждает точность положения линии»**. Технический код не показывается. `basicValidation=null` при отсутствии persisted changeSet не превращается в подтверждение точности.

## 4. Доступность команд

Все разрешения требуют подходящего actor, доступного открытого workspace и отсутствия блокирующего recovery/access/storage/protocol состояния.

| Состояние | Сохранить | Отменить | Сбросить | Изменять линию |
| --- | --- | --- | --- | --- |
| Нет local dirty | Нет | Нет | Только при persisted changeSet | Да, если линия доступна |
| Обычная допустимая local dirty | Да | Да | Только при persisted changeSet | Да |
| Исправимый отказ геометрии | После исправления candidate | Да | Только при persisted changeSet | Да |
| Отправка / ожидание повтора / чтение current | Нет | Нет | Нет | Нет |
| Unknown после повторов | Нет | Нет | Нет | Нет |
| Успех PUT, ошибка GET | Нет | Нет | Нет | Нет |
| Stale, включая завершённое чтение current | Нет | Нет | Нет | Нет |
| Потеря доступа или блокирующий сбой | Нет | Нет | Нет | Нет |

Сохранённое отличие от baseline и local dirty — независимы. Чистый local draft выбранной линии не включает Save/Cancel. Revert в этом дне не является mutation даже при доступной кнопке.

При отказе повторный Save не должен вслепую отправлять тот же заведомо отклонённый candidate. Доступность определяется исправлением и применимыми локальными проверками; серверная canonicalization/validation остаётся обязательной. Одинаковые данные после неизвестного исхода повторяет существующий recovery, а не новая пользовательская команда.

## 5. Save и Cancel

### Save

Нажатие сразу вызывает сохранение без диалога. Store сохраняет command identity и payload до HTTP; повторный click, Enter/Space или иной вызов action не создаёт параллельную новую команду. Автоматические повторы используют прежнюю identity согласно Дню 9.

Current берётся из workspace GET, не из candidate или исторического replay. После успешного завершения выбор снимается и маркер скрывается. На период запроса маркер также не доступен для редактирования. Ошибка GET после успеха PUT сохраняет отдельное состояние с блокировкой, а не завершает сценарий успехом.

No-op нельзя выводить из `operation=unchanged`: это отношение к baseline. Для текущей отправки сравниваются canonical geometry результата и snapshot current до отправки. Если исходный snapshot недоступен после recovery, используется общее сообщение о результате без недоказанного утверждения no-op. Поздний replay не подменяет актуальную карту.

### Cancel

«Отменить» немедленно возвращает local geometry к current без HTTP, сохраняет выбранную линию и маркер для следующего движения. Новый чистый local draft опирается на актуальный current и token. Отменённый candidate не удерживается как активная геометрия.

Операция выполняется атомарно в store, чтобы компоненты не реализовывали конкурирующие последовательности очистки и выбора. Существующее поведение `cancelLocalEdit`, применяемое для снятия выбора на карте, не меняется неявно.

Подтверждения Дня 10 при клике по пустому месту или другой линии сохраняются. В stale и остальных блокирующих состояниях ни кнопки, ни карта не позволяют обойти запрет на отмену/новое редактирование.

## 6. Клавиатура и фокус

- Доступные кнопки участвуют в Tab-порядке, активируются Enter/Space и имеют видимый focus indicator.
- Недоступность объясняется текстом состояния, а не только цветом или tooltip неактивной кнопки.
- Существующие модальные подтверждения карты удерживают Tab/Shift+Tab внутри; Escape закрывает их без отмены правки, фон недоступен для взаимодействия. Начальный фокус находится на безопасном действии продолжения правки.
- После закрытия диалога фокус возвращается на инициатор, а если он недоступен — на программно фокусируемый заголовок панели.
- После явного Cancel, делающего кнопку неактивной, фокус переводится на заголовок панели. При отключении сфокусированной команды после явной активации фокус также не должен теряться. Обычные асинхронные обновления статуса не перехватывают фокус пользователя.
- Статус озвучивается одной live region без дублирования сообщений и без объявления каждого drag. Ошибки доступны текстом.

Клавиатурное управление геометрией и полное соответствие всего приложения стандарту доступности не входят в заявляемый результат.

## 7. Технические границы

| Область | Ответственность |
| --- | --- |
| `components/WorkspaceEditCommands.vue` | Представление команд, статусов и пояснений |
| `components/EditorWorkOrdersView.vue` | Размещение панели над картой |
| `stores/workOrders.ts` | Единственный draft/recovery state, guards, Cancel с сохранением выбора |
| Чистая проекция состояния панели | Производные разрешения и сообщения без второго хранилища геометрии |
| `composables/map/useWorkspaceLineInteraction.ts` и `WorkspaceLineInteraction.vue` | Согласованность маркера/выбора, блокировки и существующие диалоги |
| Соответствующие tests | Переходы, HTTP counts, focus и view integration |

Pinia остаётся единственным владельцем состояния. Нет второго цикла запросов в панели. Guards выполняются и в actions, и в представлении; устаревший callback не получает права менять другой workspace/actor. Новая постоянная схема recovery ради представления статусов не требуется. Общие рефакторинги вне затронутого сценария не входят в работу.

Component/view tests используют реальный Pinia store, управляемые HTTP promises и существующие mocks карты. Одной проверки `disabled` недостаточно: повторный submit проверяется количеством запросов. Fake timers применяются к существующей retry policy без изменения её параметров.

После targeted tests выполняются из `apps/frontend`: `npm test -- --maxWorkers=2`, `npm run lint`, `npm run build`. Build включает `vue-tsc -b`. Затем `git diff --check`. Полный набор запускается после реализации, результаты не объявляются заранее.

Browser review: 1440×900, 1024×768 и 768×1024; масштаб 100% и 200%. Проверяются переносы, прокрутка, читаемость, отсутствие перекрытий, доступность кнопок и фокус. Narrow layout при увеличении масштаба не расширяет scope до смартфонов. Скриншоты и результаты сохраняются в `docs/sprint_2/`; unit tests не называются доказательством реального responsive поведения.
