# FE-04 — язык документа и название вкладки

Дата: 2026-11-07. Статус: требования, подход и [дизайн](2026-11-07-fe-04-document-language-design.md) приняты пользователем. Подготовлен [план реализации](2026-11-07-fe-04-document-language-plan.md). Итог реализации — в [отчёте](2026-11-07-fe-04-document-language-report.md); ниже сохранены основания первоначального анализа.

## Основание и границы исследования

Запрос пользователя: подробно разобрать FE-04 по материалам Sprint 2, текущему коду, Wiki и DDD_Wiki; задавать вопросы по одному, предлагать решения после прояснения требований. Артефакты сохраняются в `docs/sprint_2/`.

Исходное [frontend-ревью](frontend-review.md#fe-04--p3--русский-интерфейс-объявлен-англоязычным-документом) объединяет неверный язык HTML и неинформативный title. Предложение автора ревью — `lang="ru"`, title GeoService, HTML-проверка и screen reader smoke. Это рекомендация ревью, а не отдельно подтверждённый пользователем дизайн. В [сводном ревью](2026-10-26-deep-code-review.md) FE-04 остаётся открытой P3.

## Текущее поведение и причина

| Источник | Наблюдение | Значение для задачи |
|---|---|---|
| `apps/frontend/index.html:2` | `<html lang="en">` | Исходный документ объявляет английский язык до запуска JavaScript. |
| `apps/frontend/index.html:7` | `<title>frontend</title>` | Название вкладки отражает техническое имя frontend-проекта. |
| `apps/frontend/src/main.ts` | Vue монтирует `App` в `#app` | Монтирование приложения не заменяет корневой HTML-документ. |
| `apps/frontend/src/App.vue` | Восстановление сессии, ошибка, вход, Editor и Reviewer показываются условно внутри одного документа | Замечание относится ко всему приложению, а не только к карте редактора. |
| `LoginScreen.vue`, `App.vue`, `ReviewerHome.vue` | Основной текст прочитанных экранов русский; встречаются технические имена и Reviewer | Преобладающий язык интерфейса не совпадает с декларацией документа. |
| `apps/frontend/package.json`, `vite.config.ts` | Vue, Pinia, Vite; отдельные зависимости маршрутизации и i18n не объявлены | Действующей инфраструктуры переключения языка в проверенном frontend нет. |
| `apps/frontend/Dockerfile`, `nginx.conf` | Production собирает `dist` и отдаёт его nginx; корневой index — `index.html` | Нужно различать исходный HTML и документ из собранного приложения. |
| `apps/frontend/vite.config.ts`, `src/test/setup.ts` | Vitest использует jsdom; setup настраивает IndexedDB | Сам по себе mount Vue-компонента не доказывает правильность метаданных исходного HTML. |

Поиск по `apps` и `infra` не обнаружил присваивания `document.title`, изменения языка корневого элемента или собственного `Content-Language`. Поиск по frontend не выявил выбора языка через `navigator.language`. Атрибуты `lang="ts"` в Vue относятся к языку исходного кода и не определяют язык HTML-документа.

Непосредственная причина дефекта: несовпадающие с содержимым статические метаданные входного HTML, которые приложение не переопределяет. Шаблонное происхождение значений выглядит вероятным, но история их появления не исследовалась. Рядом присутствует `/vite.svg`; это наблюдение, не основание включать смену favicon в FE-04.

## Связь со спринтом и доменной моделью

[ТЗ Sprint 2](2026-07-31-sprint-2-technical-requirements.md), раздел 12, задаёт состояния редактора, понятные labels, клавиатурное управление и доступность controls на узком экране. В [уточнении D11-Q03](2026-10-18-day-11-user-commands-analysis.md) отдельно ограничен клавиатурный сценарий; полное соответствие приложения стандарту доступности не заявлено. Из этих материалов нельзя вывести обязательство полного accessibility-аудита в FE-04.

Прочитаны `DDD_Wiki/domains/geoservice.md`, `DDD_Wiki/use_cases/utility_editor_workflow.md`, `Wiki/actors/editor.md` и `Wiki/actors/reviewer.md`. Они определяют продукт GeoService, назначенные WorkOrder, изолированные EditVersion и различие ролей. Техническое замечание о языке не меняет эти инварианты. Если название вкладки должно отражать рабочий контекст, WorkOrder и EditVersion становятся значимыми для требований к нему; пока это открытый вопрос, а не выбранное поведение.

Поиск по Wiki/DDD_Wiki не обнаружил отдельного требования к языку интерфейса, многоязычности, локализации, screen reader или названию вкладки. Название GeoService используется в доменной модели и текущем UI, но точный формат title из этого не следует. Будущий полноценный reviewer workflow нельзя считать реализованным на основании целевой модели: текущий `ReviewerHome.vue` содержит заглушку.

Режим условной организации учтён. Организационные интервью для решения этой технической задачи не нужны. Новые доменные решения не принимались.

## Внешняя проверка смысла замечания

- [W3C: Language of Page](https://www.w3.org/WAI/WCAG22/Understanding/language-of-page.html): программно определимый основной язык помогает средствам озвучивания выбирать правила произношения. Это подтверждает механизм риска, но не доказывает конкретный результат в установленном screen reader.
- [W3C: Page Titled](https://www.w3.org/WAI/WCAG22/Understanding/page-titled.html): заголовок помогает определить назначение страницы. Документ также рассматривает изменение title при смене отдельных представлений SPA. Поэтому исправление технического имени вкладки и отображение текущего рабочего контекста — разные объёмы требований.

Эти источники объясняют проблему и не означают, что проект принял полное соответствие WCAG. Реальная озвучка зависит от используемого средства и его настроек; в этой работе она не проверялась.

## Что ещё необходимо уточнить

### Ответ пользователя — 2026-11-07

Во всех вкладках достаточно одинакового названия `GeoService`, без номера наряда и текущего состояния. Пользователь дополнительно потребовал сделать название приложения настраиваемым. Динамическое отражение рабочего контекста в title не требуется.

Пользователь уточнил: название настраивается при развёртывании; пересборка frontend допустима. Требования использовать один готовый Docker-образ с разными названиями без пересборки нет. Настройка через пользовательский интерфейс не запрошена. Механизм реализации ещё не выбран.

Пользователь подтвердил: настроенное название используется и в title, и во всех упоминаниях внутри интерфейса. Повторный поиск по `apps/frontend/src` обнаружил одно такое место в production-коде — tooltip `Выйти из GeoService` в `App.vue`. Остальные совпадения относятся к техническим ключам browser storage, IndexedDB, auth lock и тестам. Технические ключи не являются названием в интерфейсе; переименование этих ключей из требования не следует.

Проверены `infra/docker-compose.yml`, `infra/docker-compose.demo.yml`, `infra/.env.example` и `Code_wiki/deployment/docker_compose.md`. Production frontend собирается отдельным Docker stage и отдаётся как статика. Текущий Compose не передаёт название в сборку. Dev использует Vite и явно передаёт параметры окружения. Локальные `.env` исключаются из Docker context согласно runbook; настройку нельзя считать автоматически доступной внутри сборки.

Пользователь принял предложенный подход: единая настройка на этапе сборки для title и интерфейса; при отсутствующем или пустом значении используется `GeoService`, пробелы по краям обрезаются, название вставляется как обычный текст. Язык документа остаётся `ru` независимо от названия. Настройка при запуске production-контейнера рассмотрена и не выбрана: пересборка допустима, дополнительный runtime-механизм не требуется.

Существенных открытых продуктовых вопросов не осталось. Технические детали и критерии проверки изложены в дизайн-документе; его согласование отдельно от принятия подхода.
