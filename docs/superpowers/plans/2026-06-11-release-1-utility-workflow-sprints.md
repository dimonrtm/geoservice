# Крупноуровневый План Release 1 По Спринтам

Дата: 2026-06-11

## Цель Release 1

Построить новый Release 1 вокруг полного сценария `Utility GIS editor`:

`work order -> edit version -> editing -> validation -> reconcile -> conflict resolution -> review -> post -> audit`

Существующий generic GIS используется только как техническая основа там, где он не конфликтует с этим сценарием.

## Формат

- 7 спринтов по 2 недели.
- Каждый спринт должен завершаться проверяемым продуктовым инкрементом.
- Приоритет отдается целостности основного workflow, а не расширению generic GIS.
- Детальная техническая декомпозиция выполняется отдельно перед началом соответствующего спринта.

## Сводная Дорожная Карта

| Спринт | Фокус | Итоговый инкремент |
|---|---|---|
| 1 | Основа utility workflow | Пользователь входит в систему, видит назначенный work order и открывает изолированную edit version |
| 2 | Редактирование сети | Editor изменяет объекты и связи без изменения authoritative `Default` |
| 3 | Валидация | Система выявляет ошибки и блокирует небезопасное продвижение изменений |
| 4 | Reconcile и конфликты | Изменения сравниваются с актуальным `Default`, конфликты объясняются и разрешаются |
| 5 | Review и post | Reviewer принимает решение, одобренные изменения транзакционно публикуются в `Default` |
| 6 | Audit и эксплуатационная готовность | Полный путь прослеживается, demo-среда воспроизводимо восстанавливается |
| 7 | Приемка Release 1 | Основной сценарий, safety-гарантии и целевые показатели подтверждены end-to-end |

# Спринт 1. Основа Utility Workflow

## Цель

Сформировать доменную основу нового Release 1 и первый рабочий вход в сценарий.

## Крупные Блоки

- роли `Editor` и `Reviewer`;
- utility dataset и базовая модель сети;
- work orders и edit versions;
- назначение work order пользователю;
- начальный workspace для Editor.

## Результат

Editor входит в систему, видит назначенный work order, создает или открывает edit version и просматривает рабочий участок сети.

## Критерий Завершения

Первый участок workflow работает от login до открытия изолированного workspace на воспроизводимых demo-данных.

# Спринт 2. Изолированное Редактирование

## Цель

Дать Editor возможность изменять utility network внутри edit version, не затрагивая authoritative `Default`.

## Крупные Блоки

- редактирование геометрии и атрибутов utility features;
- изменение network associations;
- хранение change set;
- отображение исходного и измененного состояния;
- сохранение изменений между пользовательскими сессиями.

## Результат

Editor выполняет связанный набор изменений объекта и ассоциации, а исходное состояние `Default` остается неизменным.

## Критерий Завершения

Edit version обеспечивает устойчивую изоляцию изменений и содержит все данные, необходимые для последующей проверки.

# Спринт 3. Валидация Изменений

## Цель

Предотвращать продвижение заведомо некорректных или неполных изменений.

## Крупные Блоки

- запуск validation для edit version;
- проверки геометрии, атрибутов и network associations;
- разделение blocking issues и warnings;
- объяснимое отображение результатов Editor;
- повторная validation после исправлений.

## Результат

Editor видит конкретные проблемы, исправляет их и получает подтверждение, что edit version готова к reconcile.

## Критерий Завершения

Edit version с blocking issues нельзя продвинуть дальше, а успешная validation открывает следующий этап workflow.

# Спринт 4. Reconcile И Разрешение Конфликтов

## Цель

Безопасно сопоставлять изменения Editor с актуальным authoritative состоянием.

## Крупные Блоки

- сравнение `Base`, `Mine` и текущего `Default`;
- обнаружение geometry, attribute и association conflicts;
- понятное объяснение причины каждого конфликта;
- выбор и сохранение разрешения;
- защита от устаревания результата reconcile.

## Результат

Editor видит различия между своей версией и актуальным `Default`, разрешает конфликты и подготавливает непротиворечивый change set.

## Критерий Завершения

Неразрешенные или устаревшие конфликты блокируют отправку на review; согласованная edit version может быть отправлена Reviewer.

# Спринт 5. Review И Transactional Post

## Цель

Завершить основной продуктовый workflow безопасной проверкой и authoritative публикацией.

## Крупные Блоки

- очередь версий для Reviewer;
- просмотр change set, validation и conflict resolutions;
- решения approve и reject;
- separation of duties;
- транзакционный post в `Default`;
- защита от частичной публикации и устаревших данных.

## Результат

Reviewer принимает обоснованное решение. Одобренная версия целиком публикуется в `Default`, отклоненная возвращается Editor без потери изменений.

## Критерий Завершения

Полный путь от work order до безопасного post работает end-to-end, а protective failures не изменяют `Default`.

# Спринт 6. Audit И Эксплуатационная Готовность

## Цель

Сделать demo-сценарий воспроизводимым, наблюдаемым и проверяемым после выполнения.

## Крупные Блоки

- append-only audit основных действий и решений;
- связь событий с пользователем, work order и edit version;
- минимальная observability workflow;
- воспроизводимые seed, reset и `full-clean`;
- demo-инструкция и диагностика типовых проблем.

## Результат

После завершения сценария можно восстановить последовательность действий, проверить итоговый `Default` и вернуть среду в исходное состояние.

## Критерий Завершения

Demo запускается и повторяется по инструкции, а post и защитные отказы подтверждаются audit и техническими сигналами.

# Спринт 7. Приемка И Закрытие Release 1

## Цель

Подтвердить готовность нового Release 1 как целостного `Utility GIS editor` demo.

## Крупные Блоки

- end-to-end приемка полного workflow;
- regression-проверка safety blockers;
- проверка целевых времен на reference hardware;
- проверка reset и повторяемости demo;
- актуализация документации нового Release 1;
- фиксация известных ограничений и следующего горизонта.

## Результат

Основной сценарий подтвержден на `synthetic_utility_feeder_01`, защитные механизмы работают, документация соответствует фактическому продукту.

## Критерий Завершения

Выполнен Definition of Done Release 1 и отсутствуют открытые блокирующие дефекты основного workflow.

## Definition Of Done Release 1

- Полный workflow от work order до audit выполняется в локальной Docker Compose среде.
- Только одобренный Reviewer change set может изменить authoritative `Default`.
- Validation, unresolved conflicts, stale state и нарушение separation of duties блокируют post.
- Protective failures сохраняют edit version и не допускают частичного изменения `Default`.
- Audit позволяет проследить основные действия, решения и результат публикации.
- Demo dataset восстанавливается через reset и `full-clean`.
- Основной сценарий подтвержден автоматизированной и ручной приемкой.

## Вне Release 1

- отдельный generic GIS editor как самостоятельный продуктовый сценарий;
- analytics и dashboard-функции;
- расширенный `Project` management;
- production rollout и enterprise administration;
- масштабная библиотека utility rules за пределами demo-сценария;
- кадастровый сценарий;
- полноценное multi-user live co-editing.
