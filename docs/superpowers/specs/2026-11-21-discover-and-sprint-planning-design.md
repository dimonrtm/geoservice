# Долгосрочное исследование модели и планирование спринта от результата

## Выбранный подход

Для `/discover` выбран обзор всей доменной модели при каждом запуске. Исследование одной темы из активной очереди позволяло углубиться в неё, но оставляло за пределами отбора пробелы в других процессах. Очередь остаётся источником кандидатов и сведений о прошлых ответах.

Для `/plan-sprint` рассматривали сохранение текущей процедуры, улучшение только отбора вопросов и планирование от демонстрируемого результата. Выбран третий подход. Качество отбора важно, но даже хорошие вопросы о разрозненных задачах сами по себе не определяют, что пользователь сможет сделать к концу спринта.

## Как работает `/discover`

1. По `Wiki/` и `DDD_Wiki/` обозреть предметные процессы, участников, жизненные циклы, правила, исключения и связи между контекстами. Искать также ситуации, для которых в модели пока отсутствуют понятие, участник или правило. Сверить находки с реестрами, очередью и последними решениями.
2. Внутренне сформировать **150 вопросов-кандидатов по всей модели**. Для каждого установить, какие возможные ответы по-разному изменят модель. Объединить смысловые дубли, отсеять уже отвеченные вопросы и вынести проверки конкретного кода или данных в техническую сверку.
3. Выбрать **топ-15** по последствиям ошибки, степени неопределённости и влиянию ответа на другие правила или процессы. При равной значимости отдавать место отдельной неисследованной теме. Если после фильтра не хватает кандидатов, расширить поиск по другим процессам, их стыкам и ранее пропущенным сценариям. Срок разработки и близость к текущему спринту в отборе не участвуют.
4. Показать 15 вопросов, сгруппированных по предметным ситуациям. У каждого указать известное основание, открытый вопрос и ожидаемое изменение модели. Доменные вопросы адресовать экспертной персоне `expert_repson`, продуктовый выбор — пользователю. Ответы служат основанием для последующего уточнения модели. Вопрос сам по себе остаётся открытым.

Предлагаемое поведение параметров: `--context` и `--phase` задают акцент обзора. Например, контекст наряда привлекает внимание к его связям с сетью, правами и приёмкой. Остальные области по-прежнему участвуют в отборе. Команда работает и при пустой активной очереди. Требование 75 источников относится к отдельно запрошенному исследованию после discovery.

## Как работает `/plan-sprint`

1. Начать с результата, который можно предъявить через 14 дней. Указать, кто выполняет действие, с какими данными и по какому наблюдаемому признаку можно принять результат. Сверить исходное состояние с реализацией, принятыми доменными решениями и доступными проверками.
2. Когда возможны две содержательно разные цели, сравнить их по пользе, зависимостям и риску, рекомендовать одну и вынести существенный продуктовый выбор пользователю. При уже заданной цели сразу прорабатывать её.
3. Сохранить внутренний отбор **15 из 150** вопросов о спринте. Для каждого из 15 указать решение, на которое влияет ответ: состав работ, последовательность или приёмка. Известный ответ привести с основанием. У пользователя уточнять только оставшиеся продуктовые развилки.
4. Спланировать минимальный сквозной сценарий, его зависимости, способ проверки, контрольные точки и календарь. Отдельно указать, какую часть объёма можно снять при задержке и какой результат после этого останется проверяемым. Для случая, когда сократить сценарий без потери цели невозможно, назвать условие пересмотра цели.

Обе команды запускаются самостоятельно. При отборе работ в спринт учитываются результаты discovery, от которых зависит выбранная цель.

## Проверка изменений

- При пустой очереди и закрытой предыдущей теме `/discover` формирует межконтекстный топ-15. По каждому вопросу видно, какое решение остаётся открытым, даже если его реализация пока не запланирована.
- Для заданной цели `/plan-sprint` сразу строит проверяемый сценарий. Для двух конкурирующих целей объясняет, какой выбор изменит план. В обоих случаях по плану понятно, что показать на приёмке и как поступить при задержке.
- При изменении скиллов согласовать действующие инструкции в `AGENTS.md`, руководстве по работе с wiki и методических файлах, где прямо описан отбор вопросов. Исторические материалы по прошлым исследованиям и спринтам сохраняют исходный смысл.
