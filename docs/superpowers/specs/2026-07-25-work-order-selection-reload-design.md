# Сохранение Выбора WorkOrder После Reload

Дата: 2026-07-25

Статус: одобрено

## Контекст

`EditorWorkOrdersView` показывает `WorkspaceDetailsPanel`, когда в
`workOrders` store установлен `selectedWorkOrderId`. Сейчас простой выбор
WorkOrder существует только в памяти Pinia store, поэтому reload страницы
сбрасывает и выбор, и preview-панель.

Существующий механизм `geoservice:opened-workspace` решает другую задачу:
сохраняет пару `{workOrderId, editVersionId}` только после успешного открытия
workspace. Он не покрывает WorkOrder, который выбран для просмотра preview, но
ещё не открыт.

## Цель

После reload текущей вкладки восстановить последний выбранный WorkOrder и
снова показать его панель, если WorkOrder по-прежнему назначен текущему
пользователю.

## Не Входит В Объём

- сохранение выбора после закрытия вкладки или перезапуска браузера;
- синхронизация выбора между вкладками;
- URL/deep-link для выбранного WorkOrder;
- кеш нескольких workspace;
- изменения backend или API-контрактов;
- автоматическое открытие workspace только из-за выбора WorkOrder.

## Решение

### Независимые Маркеры В `sessionStorage`

Store использует два независимых маркера:

- `geoservice:selected-work-order` хранит `{workOrderId}` последнего выбора;
- существующий `geoservice:opened-workspace` хранит
  `{workOrderId, editVersionId}` текущего открытого workspace.

Новый маркер содержит только идентификатор. Данные WorkOrder продолжают
загружаться из `GET /api/v1/work-orders/assigned-to-me`; `sessionStorage` не
становится источником бизнес-данных.

### Выбор WorkOrder

`selectWorkOrder(workOrderId)` сравнивает новый идентификатор с текущим:

- повторный выбор того же WorkOrder ничего не сбрасывает;
- выбор другого WorkOrder очищает открытый workspace из памяти store и удаляет
  `geoservice:opened-workspace`;
- после этого новый `selectedWorkOrderId` записывается в store и
  `geoservice:selected-work-order`.

Очистка относится только к клиентскому состоянию. Серверная `EditVersion` не
закрывается и не удаляется. При последующем возврате пользователь нажимает
`Продолжить`: существующий идемпотентный `POST /edit-versions` возвращает
активную `EditVersion`, после чего frontend загружает workspace через `GET`.

Так store не держит и не загружает скрытый workspace WorkOrder, который
пользователь уже покинул.

### Reload И Восстановление

После успешной загрузки назначенных WorkOrder store согласует сохранённые
маркеры с актуальным списком:

1. Читает `geoservice:selected-work-order`.
2. Восстанавливает `selectedWorkOrderId`, только если такой WorkOrder есть в
   назначенном списке.
3. Проверяет `geoservice:opened-workspace`.
4. Если идентификаторы выбранного и открытого WorkOrder совпадают,
   восстанавливает workspace существующим `GET` без повторного
   `POST /edit-versions`.
5. Если идентификаторы различаются, сохраняет последний выбор, очищает старый
   маркер workspace и не выполняет скрытый `GET`.

Для обратной совместимости с уже открытыми вкладками: если новый маркер выбора
отсутствует, но существует корректный `geoservice:opened-workspace`, его
`workOrderId` становится выбранным, после чего workspace восстанавливается
обычным способом.

### Auth Lifecycle

Первоначальное восстановление того же пользователя после reload сохраняет оба
маркера до момента согласования с назначенным списком.

Явный logout, потеря сессии и смена пользователя очищают:

- состояние `workOrders` в памяти;
- `geoservice:selected-work-order`;
- `geoservice:opened-workspace`.

Это не позволяет перенести выбор или workspace между пользователями в одной
вкладке.

## Состояния UI

### Выбран WorkOrder Без Workspace

После reload панель показывает code, title, status, description и действие
`Начать` или `Продолжить` для восстановленного WorkOrder. Карта остаётся в
empty mode.

### Выбран И Открыт Один WorkOrder

Если оба сохранённых маркера относятся к одному WorkOrder, панель и карта
восстанавливают workspace через `GET`.

### Пользователь Переключился На Другой WorkOrder

Новая preview-панель появляется сразу. Старый клиентский workspace очищается.
После reload восстанавливается только новый выбор; запрос старого workspace не
выполняется.

### WorkOrder Больше Не Доступен

Если сохранённого WorkOrder нет в ответе `assigned-to-me`, выбор и связанные
маркеры очищаются. UI показывает состояние без выбора.

## Ошибки И Конкурентность

- Отсутствующий или недоступный `sessionStorage` не блокирует UI: выбор
  продолжает работать только в памяти.
- Повреждённый JSON, пустой `workOrderId` или значение неверного типа удаляются
  из `sessionStorage`.
- Ошибка загрузки списка не уничтожает сохранённый выбор: после успешной
  повторной загрузки его можно согласовать с актуальными назначениями.
- Текущая политика ошибок восстановления workspace сохраняется: временная
  network/timeout/5xx ошибка может оставить маркер для повторной попытки, а
  постоянная ошибка очищает маркер workspace. Маркер выбора при этом остаётся,
  поэтому пользователь видит preview выбранного WorkOrder.
- Если пользователь выбирает другой WorkOrder во время восстановления
  workspace, проверки request sequence и текущего `selectedWorkOrderId` не
  позволяют позднему ответу вернуть старую карту или изменить новый выбор.

## Границы Компонентов

- `apps/frontend/src/stores/workOrders.ts` владеет чтением, записью,
  валидацией и очисткой обоих маркеров, а также правилами перехода selection /
  workspace.
- `apps/frontend/src/stores/auth.ts` сообщает `workOrders` store, когда
  persisted state нужно сохранить для первоначального восстановления той же
  сессии и когда его нужно очистить.
- `apps/frontend/src/components/EditorWorkOrdersView.vue` только запускает
  загрузку и восстановление в согласованном порядке.
- `WorkspaceDetailsPanel` остаётся презентационным компонентом и не получает
  прямой зависимости от browser storage.

## Проверки

### Store Tests

- `selectWorkOrder()` записывает `{workOrderId}` в новый ключ.
- Повторный выбор того же открытого WorkOrder не очищает workspace.
- Выбор другого WorkOrder очищает workspace в памяти и
  `geoservice:opened-workspace`.
- Новая инстанция store восстанавливает выбор после загрузки назначенного
  списка.
- Совпадающие selection/workspace маркеры восстанавливают workspace через
  `GET` без `POST`.
- Различающиеся маркеры сохраняют selection, удаляют workspace marker и не
  вызывают workspace `GET`.
- Старый формат только с `geoservice:opened-workspace` восстанавливает выбор и
  workspace.
- Неизвестный, пустой или повреждённый selection marker удаляется.
- Недоступный `sessionStorage` не ломает selection.
- Поздний ответ восстановления не заменяет новый выбор.

### Auth Tests

- Первоначальная гидратация того же пользователя после reload сохраняет оба
  маркера.
- Logout, потеря сессии и смена user id очищают оба маркера.

### Component Tests

- После mount сначала загружается назначенный список, затем согласуется
  persisted state.
- Восстановленный выбор показывает preview-панель.
- После переключения с открытого `WO-1` на `WO-2` и повторного mount
  отображается preview `WO-2`, а workspace `WO-1` не запрашивается.

### Ручной Acceptance Scenario

1. Выбрать WorkOrder, не открывая workspace.
2. Убедиться, что справа отображается его preview-панель.
3. Выполнить reload вкладки.
4. Убедиться, что тот же WorkOrder выбран и preview-панель снова отображается.
5. Открыть workspace этого WorkOrder и выполнить reload.
6. Убедиться, что workspace восстановлен через существующую `EditVersion`.
7. Выбрать другой WorkOrder и выполнить reload.
8. Убедиться, что восстановлена preview-панель нового выбора, а предыдущий
   workspace не загружается.
