# Дизайн Долговременной Памяти Агентов

Date: 2026-05-30
Status: Approved for planning

## Цель

Создать в репозитории GeoService долговременную память для агентов, чтобы новый чат мог быстро восстановить релевантный контекст по текущему запросу пользователя, найти связанные файлы и после значимой работы сохранить краткий полезный итог.

Память должна быть строго локальной внутри репозитория, версионироваться в Git и не зависеть от внешних сервисов, баз данных, embeddings, package install или отдельного CLI.

## Принятые Решения

- Память хранится только в обычных Markdown-файлах внутри репозитория.
- Старт нового чата читает минимальный протокол и делает поиск по запросу пользователя.
- Агент сам добавляет память после значимой работы.
- Значимая работа - это только контекст, полезный через неделю: решения, root cause багов, неочевидные связи файлов, важные команды и устойчивые правила проекта.
- Запись памяти выполняется вручную по шаблону Markdown.
- Для быстрого поиска файлов используется ручной компактный `file-map.md`.
- Для нейтральности под разные агенты используется один корневой `AGENTS.md`, который ссылается на общий протокол.
- Записи памяти разделяются по папкам: `sessions/`, `decisions/`, `patterns/`, `bugfixes/`.
- Удаленный старый план `docs/codex-agent-long-term-memory-plan.md` не восстанавливается; новый дизайн пишется отдельно.

## Структура

```text
AGENTS.md
docs/
  agent-memory/
    README.md
    protocol.md
    file-map.md
    sessions/
    decisions/
    patterns/
    bugfixes/
```

`AGENTS.md` должен быть короткой входной инструкцией для любого агента, открывающего репозиторий. Он указывает прочитать `docs/agent-memory/protocol.md`, выполнить точечный поиск по памяти и после значимой работы добавить или обновить запись.

`docs/agent-memory/protocol.md` содержит реальные правила работы с памятью: стартовый retrieval, критерии значимой работы, формат записи, правила приватности, обновление `file-map.md` и процедуру проверки.

`docs/agent-memory/file-map.md` хранит компактную карту тем и файлов. Его задача - быстро привести агента к нужным файлам без чтения всех записей памяти.

Папки записей разделяют долговременный контекст по назначению:

- `sessions/` - итоги значимой выполненной работы.
- `decisions/` - архитектурные и продуктовые решения.
- `patterns/` - повторяемые правила реализации в этом репозитории.
- `bugfixes/` - симптомы, root cause, исправление и проверка.

## Поток Чтения

При старте нового чата агент выполняет минимальный retrieval:

1. Читает `AGENTS.md`.
2. Читает `docs/agent-memory/protocol.md`.
3. Из сообщения пользователя выделяет 3-8 ключевых слов: домен, фичу, ошибку, слой приложения, имена файлов или технологий.
4. Ищет по памяти точечно через `rg`.
5. Сначала смотрит `docs/agent-memory/file-map.md`, чтобы быстро найти связанные файлы.
6. Читает только найденные memory-записи, если они действительно относятся к задаче.
7. После этого продолжает обычное исследование репозитория через `rg`.

Агент не загружает все записи памяти и не читает последние N записей без причины. Это сохраняет низкий расход токенов.

Примеры поиска:

```powershell
rg -n "realtime|websocket|typecheck" docs/agent-memory
rg -n "auth|login|jwt" docs/agent-memory/file-map.md docs/agent-memory
```

## Поток Записи

После каждой значимой работы агент сам добавляет запись памяти, если результат будет полезен через неделю.

Сохранять нужно:

- архитектурные и продуктовые решения;
- багфиксы с симптомом, root cause, исправлением и проверкой;
- неочевидные связи между файлами;
- важные команды проверки или запуска;
- устойчивые patterns, которые уже реально применены;
- существенные ограничения проекта.

Не сохранять:

- полный текст чата;
- промежуточные рассуждения;
- мелкие действия без долгосрочной пользы;
- секреты, токены, пароли, `.env`;
- build output, временные логи, непроверенные догадки.

После работы агент:

1. Выбирает тип записи: `sessions`, `decisions`, `patterns` или `bugfixes`.
2. Создает Markdown-файл с датой и ASCII slug: `YYYY-MM-DD-short-slug.md`.
3. Заполняет обязательный шаблон записи.
4. Обновляет `file-map.md`, если появились новые устойчивые связи "тема -> файлы".
5. Показывает пользователю измененные memory-файлы вместе с остальными изменениями.

Подтверждение перед записью не требуется. Если запись фиксирует явное пользовательское предпочтение или спорное архитектурное решение, агент обязан формулировать его осторожно и не добавлять факты, которых пользователь не говорил.

## Формат Файлов

Минимальный `AGENTS.md`:

```markdown
# Agent Instructions

Before working in this repository:

1. Read `docs/agent-memory/protocol.md`.
2. Search `docs/agent-memory/file-map.md` and memory entries for context related to the user's request.
3. After significant work, add or update a memory entry.
```

Компактный `file-map.md`:

```markdown
# File Map

## Frontend

- map realtime websocket: `apps/frontend/src/composables/map/useLayerRealtime.ts`, `apps/frontend/src/contracts/realtime.ts`
- auth login session: `apps/frontend/src/stores/auth.ts`, `apps/frontend/src/api/auth.ts`

## Backend

- websocket layer auth: `apps/backend/app/api/ws_layers.py`, `apps/backend/app/api/websocket_auth.py`
```

Шаблон memory-записи:

```markdown
# Short Title

Date: YYYY-MM-DD
Type: session | decision | pattern | bugfix
Tags: frontend, realtime, websocket
Related files:

- `apps/frontend/src/example.ts`

## Summary

Коротко, что должен помнить следующий агент.

## Context

Почему это важно и когда применять.

## Actions

- YYYY-MM-DD: Что было сделано и результат.

## Verification

Команды проверки и итог. Если не проверялось, явно указать почему.

## Retrieval Hints

Слова и фразы, по которым эту запись должен найти будущий агент.
```

Человеческие поля пишутся на основном языке чата, в этом репозитории обычно на русском. Пути, команды, типы, API и идентификаторы не переводятся.

Если запись заменилась новой, старую запись не удалять без причины. Вместо этого добавить в метаданные строку:

```markdown
Superseded by: docs/agent-memory/<folder>/<new-entry>.md
```

## Проверка

Так как в MVP нет CLI и валидатора, проверка процедурная.

Перед завершением работы агент проверяет:

- новая запись лежит в правильной папке;
- имя файла имеет формат `YYYY-MM-DD-short-slug.md`;
- есть все обязательные секции;
- `Related files` существуют в репозитории или явно помечены как планируемые;
- `file-map.md` обновлен, если появились новые устойчивые связи "тема -> файлы";
- в памяти нет секретов, токенов, паролей, `.env` значений и полного текста чата;
- запись действительно полезна через неделю.

Smoke-проверка retrieval:

```powershell
rg -n "<ключевые слова>" docs/agent-memory
```

Ожидаемый результат: поиск находит релевантную запись или строку в `file-map.md`, а найденный контекст ведет к правильным файлам.

## Acceptance Criteria

- Новый чат обнаруживает workflow памяти через `AGENTS.md`.
- Агент читает только минимальный протокол и делает поиск по запросу пользователя.
- Память хранится в `docs/agent-memory/` и ревьюится через Git.
- Быстрый поиск файлов поддерживается через компактный `file-map.md`.
- Записи разделены по `sessions/`, `decisions/`, `patterns/`, `bugfixes/`.
- После значимой работы агент сам добавляет или обновляет memory-запись.
- Формат записи содержит summary, context, related files, actions, verification и retrieval hints.
- В MVP нет CLI, JSONL, базы данных, embeddings, внешнего сервиса или package install.
- Память не содержит секретов, полных чатов, временного шума и непроверенных догадок.

## Риски И Смягчения

- Риск: агенты начнут сохранять слишком много шума. Смягчение: протокол определяет "значимую работу" как контекст, полезный через неделю.
- Риск: ручной формат будет нарушаться. Смягчение: строгий шаблон и процедурная проверка перед завершением работы.
- Риск: keyword search пропустит контекст. Смягчение: `Retrieval Hints` в каждой записи и компактный `file-map.md`.
- Риск: память устареет. Смягчение: использовать `Superseded by` и обновлять `file-map.md` при изменении устойчивых связей.
- Риск: секрет попадет в Git. Смягчение: протокол явно запрещает секреты и требует ручной проверки перед завершением.

## Future Work

- Добавить CLI или валидатор, если ручной формат начнет ломаться.
- Добавить generated index, если записей станет слишком много для удобного `rg`.
- Добавить локальный semantic index только после доказанной необходимости и без внешних сервисов.
- Подключить CI-проверку структуры памяти, если появится валидатор.
