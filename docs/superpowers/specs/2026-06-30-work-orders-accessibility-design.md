# Accessibility-семантика экрана «Мои наряды»

Дата: 2026-06-30
Статус: согласован для written spec
Расположение: `docs/superpowers/specs`

## Назначение

Экран `Мои наряды` в `EditorWorkOrdersView.vue` уже показывает пользователю
состояния списка, выбранный `WorkOrder` и ошибки загрузки или открытия рабочей
версии. Сейчас часть этих состояний передается только визуально: через текст,
подсветку карточки и расположение сообщения рядом с нарядом.

Цель изменения - добавить точную accessibility-семантику, чтобы скринридеры и
другие assistive technologies получали те же ключевые состояния, которые видит
зрячий пользователь. Изменение не должно менять backend, Pinia store, API
контракты или визуальный UX.

## Границы Scope

Входит:

- только `apps/frontend/src/components/EditorWorkOrdersView.vue`;
- обычные состояния панели списка: загрузка, пустой список;
- ошибка загрузки назначенных нарядов;
- выбранный наряд в списке;
- ошибка открытия рабочей версии у конкретного наряда;
- component tests в `apps/frontend/src/components/EditorWorkOrdersView.test.ts`.

Не входит:

- `LoginScreen.vue`, `MapView.vue` и другие экраны;
- backend API и error contract;
- изменение Pinia store `workOrders`;
- новый listbox/option keyboard pattern;
- изменение поведения выбора наряда;
- перевод кнопки выбора наряда в toggle button.

## Выбранный Подход

Используется точечная ARIA-семантика поверх существующего нативного HTML:

- `ul/li` остаются структурой списка;
- выбор наряда остается обычной `button`;
- обычные динамические состояния получают `aria-live="polite"`;
- ошибки получают `role="alert"`;
- выбранный наряд получает `aria-current="true"`;
- `aria-pressed` для кнопки наряда не используется.

Этот вариант сохраняет текущую модель взаимодействия. Он не навязывает экрану
полный `listbox` pattern, потому что такой pattern потребовал бы отдельного
управления клавиатурой стрелками, активным потомком или перемещением focus.

## Accessibility Design

### Обычные состояния списка

Состояния `Загружаем назначенные наряды...` и `Назначенных нарядов нет.`
должны объявляться как спокойные live regions:

```html
aria-live="polite"
aria-atomic="true"
```

`polite` означает, что assistive technology может озвучить изменение без
немедленного перебивания текущей речи. `aria-atomic="true"` делает сообщение
цельным: пользователь слышит весь текст состояния, а не только изменившийся
фрагмент.

### Ошибка загрузки списка

Ошибка `workOrders.errorMessage` должна иметь `role="alert"`.

Это важно, потому что ошибка появляется после асинхронного действия `loadAssigned`.
Фокус при этом может оставаться на кнопке `Обновить` или `Повторить`, а
пользователь скринридера все равно должен услышать, что список не загрузился.

### Выбранный наряд

Кнопка выбранного наряда должна получать:

```html
aria-current="true"
```

Для невыбранных нарядов атрибут не рендерится. Так визуальная подсветка
`isSelected` получает семантический эквивалент. В один момент времени
`aria-current="true"` должен быть максимум у одного наряда.

### Ошибка открытия наряда

Сообщение `openError(workOrder.id)` рядом с конкретным нарядом должно иметь
`role="alert"`. Это покрывает ошибки цепочки открытия рабочей версии:

- `POST /api/v1/work-orders/{workOrderId}/edit-versions`;
- `GET /api/v1/work-orders/{workOrderId}/edit-versions/{editVersionId}/workspace`.

Сообщение остается рядом с тем нарядом, к которому относится ошибка, а `role`
делает его появление слышимым без ручного перемещения focus.

### Почему не aria-pressed

`aria-pressed` описывает toggle button: кнопку, которая имеет включенное или
выключенное состояние и обычно может переключаться повторным нажатием.

Выбор наряда в текущем UX не является toggle-поведением. Повторный клик по
выбранному наряду не выключает выбор, а делает тот же наряд текущим. Поэтому
`aria-current` точнее описывает состояние: это текущий элемент внутри набора
нарядов.

## Error Handling

Новые ARIA-атрибуты не меняют источники ошибок и тексты сообщений. Существующие
сообщения остаются пользовательскими текстами на русском языке. Изменяется
только способ объявления этих сообщений assistive technologies.

Если несколько ошибок существуют одновременно, каждая остается в своей текущей
области: общая ошибка списка в состоянии панели, ошибка открытия - рядом с
соответствующим `WorkOrder`.

## Testing

`apps/frontend/src/components/EditorWorkOrdersView.test.ts` нужно расширить
проверками:

- loading state имеет `aria-live="polite"` и `aria-atomic="true"`;
- empty state имеет `aria-live="polite"` и `aria-atomic="true"`;
- ошибка загрузки списка имеет `role="alert"`;
- выбранный work order имеет `aria-current="true"`;
- невыбранный work order не имеет `aria-current`;
- ошибка открытия work order имеет `role="alert"`;
- на кнопках выбора work order нет `aria-pressed`.

Regression gate:

```powershell
npm run test -- --run src/components/EditorWorkOrdersView.test.ts
npm run typecheck
```

## Последствия

Экран `Мои наряды` станет понятнее для пользователей скринридеров без изменения
визуального поведения. Состояния загрузки и пустого списка будут объявляться
спокойно, ошибки - как alert, а выбранный наряд будет представлен не только
цветом и рамкой, но и семантическим состоянием.

Изменение остается локальным для `EditorWorkOrdersView.vue`, поэтому риск
регрессии ограничен компонентом и его тестами.
