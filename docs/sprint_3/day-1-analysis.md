# День 1. Что уже определено для сохранения двух линий

Пример данных для `WO-001` опирается на штатные геометрии линий `L-003` и `L-002`. Исходные координаты сверены с файлами демоданных. Локальное демо в ходе этого разбора не запускалось. Формат записи и чтения, ответы для каждой ревизии и проверка совместимости описаны в [утверждённом контракте дня 1](day-1-command-contract.md).

## Исходный наряд

В синтетическом наборе для `WO-001` положение общего конца `J-003` равно `[65.520, 44.820]`. Координаты в таблице идут от начала линии к концу, в порядке долгота, широта. Весь контур каждой линии попадает в прямоугольную область наряда. [Сетевые объекты и соединения](../../apps/backend/seeds/specs/seed_utility_dataset_specs.py) · [Область наряда](../../apps/backend/seeds/specs/seed_work_order_specs.py)

| Линия | Идентификатор | Исходные координаты | Действие по требованиям |
| --- | --- | --- | --- |
| `L-003` | `6c13a4d8-8d67-4fb3-a1f9-4ea5ab7f0213` | `[65.520, 44.820] → [65.525, 44.8205] → [65.530, 44.820]` | Сдвинуть среднюю вершину, сохранив концы. |
| `L-002` | `6c13a4d8-8d67-4fb3-a1f9-4ea5ab7f0212` | `[65.510, 44.820] → [65.520, 44.820]` | Вставить между концами первую внутреннюю вершину с видимым изгибом. |

Для ручного демо редактор открывает один штатный `WO-001` без сохранённых правок. В ходе прогона он меняет обе линии на карте и сохраняет их вместе. После нового входа видны обе правки. Затем редактор откатывает `L-003` и снова входит в тот же наряд. Теперь видна только правка `L-002`, все три её точки совпадают с результатом общего сохранения. [Критерии Р-01–Р-07](acceptance-criteria.md)

## Что должно быть видно при повторном чтении

| Момент | Линии с отличием от исходного снимка | Что проверяет наблюдатель |
| --- | --- | --- |
| Открыта чистая версия | Нет | Обе исходные геометрии доступны. Два локальных черновика до отправки не влияют на серверное чтение. |
| Сохранены обе правки | `L-003`, `L-002` | Обе новые геометрии читаются в одной новой ревизии. Для каждой доступны исходный контур и сохранённый изгиб. |
| Возвращена только `L-003` | `L-002` | Средняя вершина `L-003` снова на исходном месте. Все три координатные пары `L-002` совпадают с общим сохранением. |
| В отдельном прогоне первой возвращена `L-002` | `L-003` | У `L-002` ровно две исходные точки. Сдвиг на `L-003` сохранён. |
| Возвращена последняя изменённая линия | Нет | Обе линии совпадают с исходным снимком. История команд сохраняется. |
| После выборочного отката повторена команда общего сохранения | Состав после отката | Ответ на повтор воспроизводит исход первого сохранения. Отдельное чтение показывает более позднюю ревизию. Повтор не добавляет события и не возвращает отменённый изгиб. |

Только для автотеста совместимости А-07 нужна рабочая версия Sprint 2 с сохранённым сдвигом `L-003` и записанным исходом её однообъектной команды. Тест открывает версию после обновления, добавляет правку `L-002`, откатывает `L-003` и повторяет старую команду. Ожидается прежний ответ команды, а при чтении текущей версии видна только правка `L-002`. [Критерий А-07](acceptance-criteria.md) · [Тест прежнего исхода после более поздней записи](../../apps/backend/utility_service/use_cases/tests/test_save_geometry_replay.py)

## Где проявляется ограничение Sprint 2

- **Доменное правило.** Сохранённая правка определяется сравнением текущей геометрии с неизменяемым исходным снимком рабочей версии. Ограничения первой реализации разрешают одно отличие на одну версию и запрещают изменение числа вершин. Это затрагивает как сохранение второй линии, так и чтение уже вставленной вершины. По критериям Sprint 3 идентификаторы, концы, исходный снимок и учтённые соединения сохраняются. [Инварианты EditVersion](../../DDD_Wiki/invariants/edit_version_persisted_edit_invariants.md) · [Определение сохранённого состава изменений](../../Wiki/specifications/edit_version_has_persisted_change_set.md) · [Проверка геометрии](../../apps/backend/utility_service/domain_services/edit_geometry/save_policy.py)
- **Ответ команды и чтение версии.** Действующий PUT адресован одной линии. В его ответе `hasPersistedChangeSet` вычисляется из `operation` этой линии. GET карты и GET состава изменений читаются отдельно, у обоих есть токен ревизии. Проекция состава изменений допускает только `null` или одну изменённую вершину. После выборочного отката у возвращённой линии значение `unchanged`, а у всей версии всё ещё есть сохранённая правка. [Маршруты API](../../apps/backend/utility_service/web_api/api/work_orders.py) · [Ответ записи](../../apps/backend/utility_service/use_cases/schemas/edit_version/geometry_save_out.py) · [Проекция при чтении](../../apps/backend/utility_service/use_cases/services/version_change_projection.py)
- **Журнал.** Запись команды содержит один обязательный `feature_id`, отпечаток запроса и сохранённый исход. У события первичный ключ `command_id`, уникальная пара «версия, новая ревизия» и одна пара геометрий до и после. Вторая строка события под тем же идентификатором и той же ревизией нарушила бы оба ограничения. [Запись команды](../../apps/backend/utility_service/infrastructure/postgresql/models/work_order/edit_version_command.py) · [Запись события](../../apps/backend/utility_service/infrastructure/postgresql/models/work_order/edit_version_change_event.py)
- **Браузер.** Редактор хранит один локальный черновик. Сохранённая для восстановления команда адресована одному объекту. Если в записи восстановления есть исходная геометрия, валидатор требует равенства числа её точек числу точек в отправленной геометрии. Случай вставки «две точки → три» меняет это условие. Существующая браузерная проверка воспроизводит потерю ответа после записи, повтор из той же вкладки и отдельное чтение версии. [Хранилище черновика](../../apps/frontend/src/stores/edit_version/editVersionDraft.ts) · [Формат восстановления](../../apps/frontend/src/contracts/workspace/workspace-recovery.ts) · [Браузерные проверки](../../infra/m4/README.md)

## Число изменённых линий в рабочей версии

По решению пользователя две линии задают объём приёмочного примера Sprint 3. Общего ограничения на число изменённых линий в рабочей версии нет. Если после общего сохранения `L-002` и `L-003` редактор отдельной командой сохраняет правку третьей подходящей линии, следующее чтение показывает три изменённые линии. Координаты первых двух совпадают с результатом предыдущего сохранения. [План спринта](two-line-edit-sprint.md) · [Очередь редактора](../planning/network-editor-backlog.md)

Если редактор подготовил правки трёх подходящих линий до первого нажатия «Сохранить», одно нажатие сохраняет все три одной атомарной командой. При успехе все три правки видны в одной новой ревизии. При ошибке в одной из них сохраняется состояние версии до команды. Это уточнение пользователя распространяет правило атомарности спринта на три одновременно подготовленные правки.

## Порядок линий при повторе команды

Пользователь подтвердил, что порядок редактирования линий не влияет на результат. Для повтора с тем же `commandId`, тем же контекстом и исходным токеном ревизии запросы с правками `[L-003, L-002]` и `[L-002, L-003]` выражают одну команду, если итоговая геометрия каждой линии та же. Сервер возвращает записанный исход без дополнительной ревизии и события. Внутри каждой линии последовательность вершин значима: для вставки на `L-002` критерий А-01 требует сохранить порядок «исходное начало → новая вершина → исходный конец». [Критерии А-01 и А-04](acceptance-criteria.md) · [Идентичность команды](../../Wiki/value_objects/command_id.md)

## Команды Sprint 2 после обновления

Браузер Sprint 2 сохраняет команду до отправки PUT. При обрыве связи запись может быть только у редактора. Пользователь подтвердил следующее правило совместимости для открытой версии при действующем доступе. [Проверка записи команды до отправки](../../apps/frontend/src/stores/workspace/workspace_recovery/createRecoveryExecutor.test.ts) · [Критерий А-07](acceptance-criteria.md)

| Что получил сервер после обновления | Ожидаемый результат |
| --- | --- |
| Первая доставка запроса в формате Sprint 2. Даже единственная правка `L-003` допустима и ревизия актуальна. | Сервер отклоняет запрос старого формата. Геометрия и ревизия сохраняют значения до запроса. Для нового сохранения одной линии используется формат Sprint 3. |
| Точный повтор уже выполненной команды Sprint 2 с её исходным `commandId` и содержимым | Сервер возвращает записанный исход прежней команды. Геометрия и ревизия сохраняют актуальные значения, дополнительного события нет. |
