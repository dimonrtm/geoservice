# Критерии приёмки спринта 3 — две линии в одном наряде

Спринт принят, когда редактор в одной рабочей версии `WO-001` сохраняет две правки одним действием, возвращает выбранную линию к исходной форме и после нового входа видит правильную геометрию обеих линий. Для полной приёмки нужны наблюдения из браузера и результаты автоматических проверок, перечисленных ниже. [План спринта](two-line-edit-sprint.md)

## Подготовка ручной проверки

Запустить штатное локальное демо через Docker Compose и войти в обычном браузере под редактором, которому назначен `WO-001`. Открыть наряд через «Начать» или «Продолжить». Для воспроизводимого прогона использовать демоэкземпляр, в котором у обеих линий исходная геометрия и в рабочей версии ещё нет сохранённых правок. Все действия выполняются в этом наряде. [Локальный запуск и вход](../../README.md)

| Линия | Состояние при открытии | Действие для демонстрации |
| --- | --- | --- |
| `L-003`, участок от `J-003` до `J-004` | Три вершины, включая одну внутреннюю | Сдвинуть внутреннюю вершину так, чтобы отличие от исходной формы было видно при наложении. |
| `L-002`, участок от `J-002` до `J-003` | Прямой участок из двух концов | Вставить первую внутреннюю вершину и задать ей положение с видимым изгибом. |

Обе правки выполняются внутри области наряда. Участки имеют общий конец у `J-003`. Его положение и учтённые соединения должны сохраниться. Данные синтетические. [Исходные объекты и соединения](../../apps/backend/seeds/specs/seed_utility_dataset_specs.py)

## Ручной сценарий в браузере

Выполнить шаги подряд. Сохранить обе линии один раз в шаге Р-04. Для проверок после входа каждый раз возвращаться через список нарядов к той же рабочей версии.

| Критерий | Действие редактора | Наблюдаемый результат |
| --- | --- | --- |
| Р-01. Правка существующей вершины | Выбрать на карте `L-003`, сверить её код и переместить среднюю вершину. | Выбран код `L-003`. У линии видна новая форма, оба конца остаются на месте. |
| Р-02. Вставка первой внутренней вершины | До сохранения выбрать на карте `L-002`, сверить код и добавить вершину между концами. | Выбран код `L-002`. Вместо прямого отрезка видны два сегмента с общим изгибом. Концы участка остаются на месте. |
| Р-03. Два независимых черновика | Снова выбрать `L-003`, затем вернуться к `L-002`. | Каждый раз код соответствует выбору. На `L-003` остался сделанный сдвиг, на `L-002` — вставленная вершина. Повторно вводить правки не требуется. |
| Р-04. Общее сохранение | Один раз нажать «Сохранить» и дождаться окончания операции. | Интерфейс подтверждает сохранение. Карта выделяет обе изменённые линии. Для записи второй линии дополнительных действий не требуется. |
| Р-05. Повторное открытие и сравнение | Выйти из учётной записи, войти снова и открыть `WO-001`. По очереди выбрать на карте каждую линию и посмотреть наложение исходного и сохранённого контуров. | Обе линии выделены как изменённые. У `L-003` различимо прежнее и новое положение средней вершины. У `L-002` видны исходный прямой отрезок и сохранённый изгиб. Концы каждого контура попарно совпадают. |
| Р-06. Адресный откат | Выбрать `L-003` и нажать «Вернуть L-003 к исходной форме». | `L-003` принимает исходную форму и теряет выделение сохранённой правки. `L-002` по-прежнему выделена, её изгиб сохраняется. |
| Р-07. Результат после нового входа | Ещё раз выйти, войти и открыть тот же наряд. Осмотреть обе линии. | Единственная сохранённая правка на карте относится к `L-002`. Её изгиб совпадает с увиденным в Р-05. У `L-003` средняя вершина вернулась к исходному положению. |

## Автоматические проверки

Для проверок хранения состояние считывается после завершения команды отдельным запросом. Сверяются ревизия рабочей версии, состав сохранённых правок по идентификаторам линий и упорядоченные координаты в точности, принятой сервером. Это позволяет обнаружить потерю вершины или лишнее изменение даже при визуально похожих контурах.

| Критерий | Условия и действие | Признак прохождения |
| --- | --- | --- |
| А-01. Геометрия и область наряда | Проверить перемещение внутренней вершины и вставку в двухточечную линию. Отдельными примерами задать вырожденный сегмент, перенос конца и выход геометрии за область наряда. | Обе допустимые правки проходят. У вставленной линии порядок «исходное начало → новая вершина → исходный конец». Для каждого недопустимого варианта команда отклонена и прежняя геометрия доступна для чтения. |
| А-02. Атомарность общего сохранения | Отправить обе допустимые правки. В независимых прогонах задать ошибку в геометрии второй линии и прервать транзакцию после записи первой. | При успехе обе правки читаются в одной новой ревизии. В каждом неуспешном прогоне обе геометрии, состав правок и ревизия совпадают с состоянием до команды. Журнал не содержит события о частично применённой правке. |
| А-03. Выборочный откат | Начать с двух сохранённых правок. В одном прогоне вернуть к исходной форме `L-003`, в другом — `L-002`. Затем откатить последнюю оставшуюся правку. | В каждом прогоне после первого отката в составе изменений осталась ровно одна линия, её сохранённые координаты совпадают с координатами до отката. При откате вставки `L-002` снова содержит две вершины. После последнего отката состав правок пуст. Исходный снимок и учтённые соединения сохраняются во всех состояниях. |
| А-04. Потерянный ответ и повтор | После применения общего сохранения скрыть успешный ответ от клиента. Восстановить исход по записи команды, повторить ту же команду с тем же идентификатором и содержимым. Повторить проверку для адресного отката. | Восстановление возвращает исход соответствующей команды. Повтор не добавляет ревизию или событие. Независимое чтение показывает две линии после сохранения и только оставшуюся правку после отката. |
| А-05. Устаревшая вкладка | Открыть две вкладки с одной ревизией после общего сохранения. В первой откатить `L-003`. Из второй отправить изменение или откат с прежней ревизией. | Устаревшая команда получает отказ. Повторное чтение из второй вкладки показывает исходную `L-003` и сохранённый изгиб `L-002`. Ревизия после отказа совпадает с ревизией успешного отката. |
| А-06. Доступ и изоляция | Проверить общее сохранение без права редактировать наряд и команду, где одна из линий не принадлежит доступной рабочей версии. Проверить смену пользователя при наличии локальных черновиков или отправленной команды. | Сервер отклоняет недопустимую запись целиком. У нового пользователя отсутствуют черновики предыдущего редактора, вход не отправляет его изменения автоматически. |
| А-07. Совместимость с данными Sprint 2 | Подготовить прежнюю рабочую версию с сохранённой правкой `L-003` и исходом её однообъектной команды. Открыть её после обновления, добавить правку `L-002`, откатить `L-003` и повторить старую команду с исходным идентификатором и содержимым. | При первом открытии читается прежняя правка. После добавления читаются две, после отката — одна. Повтор старой команды возвращает её прежний исход, актуальная геометрия и ревизия при этом сохраняются. |

Для серверной части использовать `pytest` и изолированную БД через `infra\db-tests.cmd` из корня репозитория. Для клиентской логики выполнить `npm.cmd test` и `npm.cmd run typecheck` в `apps/frontend`. Для восстановления команды использовать браузерные проверки в `infra/m4`. При приёмке фиксировать, какой тест на **двух линиях** подтвердил каждый применимый случай. [Проверки восстановления](../../infra/m4/README.md) · [Основание для проверки совместимости](../sprint_2/2026-08-16-sprint-2-acceptance-report.md)

## Решение по результатам

- **Полный сценарий принят**, когда пройдены Р-01–Р-07 и А-01–А-07. Для ручной части записать наблюдения после обоих повторных входов. Для автоматической части указать тесты и результат их прогона на принимаемой версии.
- **Показана готовая часть**, если к восьмому рабочему дню воспроизводится только часть сценария или остаётся непроверенный критерий. Указать последний пройденный шаг, идентификатор оставшегося критерия и что предстоит проверить. Приёмку полного сценария перенести до закрытия этих пунктов.
