# План реализации контракта сохранения линий

**Цель.** Редактор сохраняет подходящие линии одной командой, откатывает выбранную и после нового входа видит актуальный состав правок. Формат запроса, ответов и отказов утверждён 27 ноября 2026 года. [Контракт дня 1](day-1-command-contract.md) · [Календарь спринта](two-line-edit-sprint.md)

**Архитектура.** На backend чистые правила Python определяют допустимые переходы геометрии. Прикладной сценарий через порт координирует проверку доступа, блокировку версии и транзакцию. PostgreSQL/PostGIS отвечает за хранение и пространственные предикаты, FastAPI — за JSON и HTTP. Во frontend правила черновика остаются в TypeScript, Pinia владеет состоянием редактора, адаптеры связывают его с MapLibre, HTTP и IndexedDB. [Архитектура backend](../../Code_wiki/архитектура/backend.md) · [Архитектура frontend](../../Code_wiki/архитектура/frontend.md)

**Ограничения.** Ручной прогон начинается с одного штатного `WO-001` без правок. Одна команда принимает непустой список уникальных линий. Порядок линий свободный, порядок вершин значим. Каждое фактическое изменение версии увеличивает ревизию один раз. Старый формат служит для воспроизведения записанных исходов. Пример с сохранённой до обновления `L-003` нужен для автотеста А-07. [Пример и исходные геометрии](day-1-analysis.md)

Для выполнения задач одним исполнителем предусмотрен `superpowers:executing-plans`, для работы отдельными исполнителями по задачам — `superpowers:subagent-driven-development`. Шаги ниже относятся к будущей реализации.
