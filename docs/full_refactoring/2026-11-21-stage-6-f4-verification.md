# Этап 6 · Результаты проверки F4

Один TypeScript-исполнитель управляет восстановлением Save и Revert, открытием вкладки, приостановкой после потери доступа и подготовкой к выходу. В приложении он получает реактивное состояние своего экземпляра Pinia. В тестах тот же код работает с обычным объектом и управляемыми операциями ввода-вывода. [Дизайн](2026-11-21-stage-6-f4-design.md) · [План реализации](2026-11-21-stage-6-f4-plan.md)

## Что проверено

| Сценарий | Наблюдаемый результат |
| --- | --- |
| Save и Revert | Первая отправка ждёт записи команды в IndexedDB. При неизвестном исходе повторяется исходная команда. После подтверждённого успеха сбой чтения допускает повторный GET. Новый PUT для этого не требуется. |
| Открытие вкладки | При загрузке исполнитель различает неизвестный исход, подтверждённый успех и ожидание согласия. Сбой старой загрузки после смены пользователя не блокирует Save. Ошибка загрузки текущего пользователя блокирует его до отправки. |
| Потеря доступа | Восстановление приостанавливается. Для продолжения нужны подтверждение для той же команды и актуальная сессия. Если успех уже известен, возобновляется только чтение. |
| Подготовка к выходу | Выход ждёт незавершённой записи команды. Ошибка записи блокирует подготовку. Долговременная копия позволяет завершить подготовку, даже если ответ сервера ещё не пришёл. |

Позднюю ошибку загрузки воспроизвели до исправления. Сначала Алексей начал загрузку, затем Мария вошла и успешно загрузила свои записи. Ошибка Алексея выставила ошибку хранилища у Марии. Теперь исполнитель проверяет поколение загрузки и текущего пользователя перед публикацией и успеха, и ошибки. Парный тест проверяет, что собственная ошибка Марии по-прежнему блокирует отправку. [Исполнитель](../../apps/frontend/src/stores/workspace/workspace_recovery/createRecoveryExecutor.ts) · [Тесты сценариев](../../apps/frontend/src/stores/workspace/workspace_recovery/createRecoveryExecutor.test.ts)

При ревью извлечения обнаружили ещё один случай. Если редактор выбрасывает исключение при применении уже прочитанного снимка, нужно сохранить квитанцию и дать повторить чтение. Ошибку воспроизвели тестом, затем восстановили обработку. Тест проверяет, что второй GET завершает операцию, а PUT за весь сценарий отправляется один раз.

## Особенность повторной установки редактора

Если редактор переустанавливается в том же экземпляре Pinia для того же пользователя во время GET, старое чтение отменяется. Запись с квитанцией сохраняется, но при такой переустановке чтение автоматически не возобновляется. Тест вызывает `retryRead` через новый редактор и проверяет ровно одно завершение. Кнопка повтора в этом случае может отсутствовать, поскольку отмена сама по себе не выставляет ошибку чтения. Такое поведение было и до F4. При полной перезагрузке вкладки создаётся новый экземпляр Pinia и восстановление запускается штатно. [Тест жизненного цикла](../../apps/frontend/src/editor/editorRuntime.test.ts)
