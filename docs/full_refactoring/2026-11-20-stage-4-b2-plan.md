# Этап 4 · План реализации B2

Для выполнения по шагам — `superpowers:executing-plans` или `superpowers:subagent-driven-development`, в зависимости от выбранного режима.

**Цель.** Отделить весь Open от SQLAlchemy и ORM, сохранив атомарное создание версии, переоткрытие и HTTP-контракт. [Принятый дизайн](2026-11-20-stage-4-b2-design.md).

**Архитектура.** Прикладной сценарий владеет порядком действий в двух последовательных транзакциях. Контекст предоставляет операции чтения и записи. Адаптер PostgreSQL использует существующие репозитории, завершает транзакцию и распознаёт причину конфликта. Стек — Python, pytest, FastAPI, SQLAlchemy, asyncpg, PostgreSQL/PostGIS.

Пути и команды ниже даны от `apps/backend`. Для интеграционных тестов использовать штатное backend-окружение, `RUN_DB_TESTS=1` и `TEST_DATABASE_URL`, указывающий на отдельную PostGIS с именем базы, оканчивающимся на `_test`. Тестовая конфигурация сама подставляет этот адрес в `DATABASE_URL`. Пропущенный тест БД не подтверждает приёмку. Изменения оставлять в рабочем дереве для ревью пользователя.

## Случаи для особого внимания

| Ситуация | Проверяемый исход | Шаг |
| --- | --- | --- |
| Наряд сменил исполнителя или редактор потерял права после отката | Вторая попытка возвращает действующую ошибку доступа до обновления времени | 1 |
| Сбой случился на выходе из транзакции | Результат открытия не выдан. Сбой отката или второй попытки не запускает новое восстановление | 1–2 |
| Драйвер назвал другое ограничение, а текст содержит имя индекса Open | Исходная ошибка доходит до вызывающего кода | 2 |
| Конкурентные запросы сериализовались до вставки | Отдельно подтверждены и единственная версия, и реальный конфликт индекса | 2, 4 |
| Тестовые клиенты используют ORM или прежний общий сервис Open/Save | Результат читается после закрытия сессии. Обе очередности блокировки Open/Save по-прежнему проверяются | 3–4 |

## Результат реализации

[OpenEditVersionService](../../apps/backend/utility_service/use_cases/services/open_edit_version.py) координирует обе попытки и возвращает неизменяемый снимок. [PostgresOpenEditVersionTransactions](../../apps/backend/utility_service/infrastructure/postgresql/open_edit_version.py) удерживает блокировку до завершения попытки и преобразует только подтверждённое нарушение уникальности после отката. Реальный конфликт индекса и конкурентное штатное открытие проверены раздельно.

При реализации обнаружилось, что в сессии с уже загруженным нарядом получение блокировки могло вернуть прежнее назначение из ORM. В чтение под блокировкой добавлено обновление объекта из строки БД. Интеграционный тест сначала воспроизвёл успешный Open для прежнего исполнителя, затем подтвердил ожидаемый отказ. [Проверка переназначения](../../apps/backend/tests/integration_tests/test_open_edit_version_transaction.py).

Ревью выявило пробел в HTTP-тесте. Теперь ответы 201 и 200 проверяются по всем семи полям снимка с разными значениями createdAt и lastOpenedAt. В тестовой фикстуре межконтекстной согласованности удаление корня версии использует существующий каскад для объектов и команд. Это устранило нарушение внешнего ключа при запуске этих тестов после конкурентного Save. Соответствующая последовательность прошла все 14 проверок.

| Итоговая проверка | Результат |
| --- | --- |
| Полный backend pytest без флага БД | 857 прошли, 337 интеграционных пропущены |
| Отдельный прогон tests/integration_tests на чистой PostGIS | Все 337 прошли |
| Ruff и Black по 20 изменённым файлам Python | Успешно |

В обоих прогонах pytest выдал одно предупреждение из passlib об устаревшем модуле crypt. Временный контейнер PostGIS и сеть тестового проекта удалены. Изменения оставлены в рабочем дереве для ревью.

Проверка `check-memory-needed.py --check` указала на подготовленное изменение `AGENTS.md`. Правило владения прикладными типами полностью записано в `AGENTS.md`, а причины выбора для Open — в дизайне B2. Отдельная запись памяти повторила бы эти источники.
