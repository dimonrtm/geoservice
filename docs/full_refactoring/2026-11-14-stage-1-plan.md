# Этап 1 — общий план реализации

> **Исполнителю:** использовать superpowers:executing-plans либо superpowers:subagent-driven-development после выбора пользователем способа выполнения. Шаги отслеживать через `- [ ]`. Запрет AGENTS.md на git add/commit/push приоритетнее требований skills.

**Цель:** реализовать принятые F3, B3 и F7, сохранив ограничения редактора и HTTP-контракты.

**Архитектура:** три самостоятельных результата; F3 отделяет реактивную сборку, B3 отделяет транспортное представление ошибок, F7 проверяет входные данные и представляет ошибки строк. F7 меняет API-клиент, store и UI согласованно.

**Стек:** Vue 3, TypeScript, Pinia, Vitest, Playwright; Python 3.12, FastAPI, SQLAlchemy, pytest, PostGIS. Новые зависимости не нужны.

**Спецификация:** [принятый дизайн](2026-11-14-stage-1-design.md).

## Общие ограничения

- Backend Save/replay, readback errors, квитанции команд, схема БД и границы транзакций не изменяются.
- Сохранить epoch/requestSeq, навигацию с dirty guard, приостановку recovery при исчезновении id.
- Если выбранного id нет в полученном массиве, сохранить очистку выбора/workspace/localDraft; при общей ошибке загрузки не выдавать отсутствие списка за пустой список.
- Все позиции массива видны; пригодный id разрешает открытие при ошибках остальных полей. Ошибки называют конкретное поле; отдельной retry-кнопки нет.
- Все новые документы/отчёты — в docs/full_refactoring, русский текст, LF, UTF-8. Git add/commit/push не выполнять. Не менять чужие правки AGENTS.md.
- Тестовые ошибки окружения не объявлять дефектом приложения; исходный baseline не считать зелёным без запуска.

## Фокус проверки

1. Поздний повреждённый Open после смены выбора/сессии не меняет новый экран — тест F7-3.
2. Ошибочный status при пригодном id не блокирует Open и не превращается в assigned — тест F7-2.
3. Новый список без прежнего id очищает draft, даже если содержит повреждённую строку — тест F7-2.
4. Подтверждённый Save с отказавшим readback сохраняет правильное сообщение и блокировки — тест F3-1.
5. Отказ Open после восстановления unique violation остаётся прежним HTTP-отказом, а исторический Save replay не использует новый mapping — тест B3-1 и регрессия B3-2.
