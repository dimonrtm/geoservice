# F1 Editor State Ownership Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking. Способ выполнения выбирает пользователь. Требования skills к commit не применяются: AGENTS.md запрещает git add/commit/push.

**Goal:** устранить все взаимные записи состояния редактора, сохранив поведение и отделив владение от межмодульной координации.

**Architecture:** отдельные Pinia owners draft/commands/navigation/session предоставляют смысловые операции. Обычный TypeScript workflow координирует их через явно переданные порты; экземпляр runtime связывает адаптеры одного Pinia и RecoveryHost. F2 и F4 не включаются.

**Tech Stack:** существующие Vue 3, TypeScript, Pinia, Vitest, Vue Test Utils, fake-indexeddb, M4 Playwright; без новых runtime-зависимостей.

**Spec:** [принятый дизайн F1](2026-11-16-stage-2-f1-design.md); [анализ и ответы пользователя](2026-11-16-stage-2-f1-analysis.md).

**Выполнено 2026-11-17.** Все шесть задач закрыты. Проверки распределены между новыми unit/component tests и существующими интеграционными recovery/navigation/map tests без дублирования всей матрицы. Фактические команды, RED→GREEN, принятые уточнения и ограничение M4 «10 + успешный повтор 1» — в [verification](2026-11-17-stage-2-f1-verification.md); [итоговое ревью](2026-11-17-stage-2-f1-review.md) завершено с исправлением обоих Important замечаний. ## Global Constraints

- «F2 остаётся отдельным: HTTP → auth и auth → публичные операции редактора сохраняются».
- «F4 (recovery I/O), F6 (согласование read tokens), backend, протоколы, storage schema, retry и миграции не изменяются».
- «Внешними изменениями считаются также вложенные записи, delete, мутация полученной коллекции, `$patch` и чужой `$reset`».
- «На экземпляр Pinia — один runtime; запрещён общий singleton для всех экземпляров».
- «Окончательное прекращение Save-and-leave после unknown/rejected/readback/storage/protocol/identity/access/session сохраняется».
- «UI и map interaction вызывают workflow для межмодульных действий»; локальный preview допускает операцию commands.
- Сохранять тексты, диалоги, фокус, доступность, порядок запросов и отдельность canonical snapshot/draft/sent intent/overlay.
- Git add/commit/push не выполнять. Работать в подходящем текущем checkout; создание нового worktree без необходимости не входит в план.
- Диагностические отчёты и evidence сохранять в docs/full_refactoring; не перезаписывать старые результаты этапа 1 и sprint_2.
- Пока выполняется миграция, старая реализация может оставаться на ещё не переключённых путях; каждый шаг должен сохранять тестируемое рабочее приложение. Финальная приёмка запрещает оставшиеся обходы F1.

## Общие интерфейсы

Имена ниже фиксируют стыки задач; тела методов и небольшие private helpers выбирает исполнитель.

В `editorWorkflowContracts.ts`:

```ts
type EditorContext = {
  actorId: string; sessionEpoch: number;
  workOrderId: string; editVersionId: string; workspaceGeneration: number;
};
type DraftIdentity = EditorContext & { draftGeneration: number };
type SaveAttempt = {
  context: EditorContext; draftIdentity: DraftIdentity | null;
  commandId: string; navigationId: string | null;
};
type SaveStartResult =
  | { kind: "started"; commandId: string }
  | { kind: "not-started" }
  | { kind: "superseded" };
type EditorRuntime = { workflow: EditorWorkflow; dispose(): void };
```

`workspaceGeneration` — жизненный цикл открытого контекста, а не read generation: обычный актуальный GET не инвалидирует активный Save. Использовать отдельный счётчик при необходимости; на close/reset/reopen он меняется, на readback — нет. `draftGeneration` меняется при создании/замене/удалении попытки, но не при обычном move вершины той же попытки. Значения не сохраняются в IndexedDB.

`EditorWorkflow` предоставляет:

```ts
beginLocalEdit(featureId: string, vertexIndex: number): boolean;
moveLocalVertex(xy: [number, number]): boolean;
cancelLocalEdit(): boolean;
discardLocalChangesKeepingSelection(): boolean;
saveLocalDraft(): Promise<SaveStartResult>;
requestNavigation(target: NavigationTarget): string | null;
resolveNavigation(id: string, choice: NavigationChoice): Promise<void>;
cancelNavigation(id: string): void;
performNavigation(target: NavigationTarget): Promise<void>;
beginRevert(): "resolve-dirty" | "confirm" | "blocked";
discardLocalDraftForRevert(id: string): boolean;
confirmRevert(id: string): Promise<void>;
cancelRevert(id: string): void;
discardRejectedAttempt(): boolean;
completeRecovery(completion: RecoveryCompletion): void;
interruptRecovery(key: RecoveryKey, reason: Parameters<RecoveryHost["interrupted"]>[1]): void;
clearOpenedWorkspace(options?: ClearOpenedWorkspaceOptions): void;
resetEditor(options?: ResetWorkOrdersOptions): void;
suspendWorkspaceRecoveryForAccessLoss(actorId?: string): void;
suspendWorkOrderRecovery(workOrderId: string): Promise<void>;
```

Существующие read/open/retry entry points сохраняют сигнатуры; их согласование с owners делегируется workflow через узкие callbacks. Не переносить HTTP-чтение в pure workflow: session/read adapters остаются исполнителями чтений. `ClearOpenedWorkspaceOptions` экспортировать из session-контракта или перенести в contracts, сохранив `force`/`preserveStoredWorkspace`; `ResetWorkOrdersOptions` переиспользовать из editorSessionStorage.
