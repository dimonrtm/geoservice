# B4. Проверка реализации

Исходная ревизия — `0304fbc`, ветка `first-edit-save`. Издатель принимает синхронную функцию публикации. Транспортный адаптер формирует кадр по требованию менеджера. Менеджер подписок в `app.state` общий для HTTP CRUD, подписки и отзыва сессии. [Дизайн](2026-11-22-stage-7-b4-design.md), [план](2026-11-22-stage-7-b4-plan.md), [фабрики](../../apps/backend/utility_service/realtime_dependencies.py), [адаптер](../../apps/backend/utility_service/web_api/realtime/feature_events.py).

## Ход проверки

- На исходном коде оба сценария `test_legacy_realtime_delivery.py` прошли в изолированной PostGIS. До реализации новых границ отдельные запуски зафиксировали отсутствие внешнего модуля фабрик, отказ шести сценариев с функцией вместо менеджера, зависимость издателя от FastAPI и отсутствие нового пакета адаптера и прикладного DTO.
- После переноса фабрик прошли 83 проверки маршрутов и архитектуры и оба интеграционных сценария. После подключения адаптера прошли 66 профильных проверок и 15 интеграционных проверок доставки и ошибок после commit.
- После переноса самого менеджера отдельный запуск четырёх интеграционных модулей прошёл с результатом **24 passed**. Выполнялись `test_legacy_realtime_delivery.py`, `test_legacy_realtime_diagnostics.py`, `test_browser_auth_websocket_revocation.py` и `test_alembic_application_logging.py`.
- Первый запуск AR-03 с исходниками через Windows bind mount исчерпал время ожидания готовности. Прямой запуск сервера с этим монтированием показал успешный startup. Полная проба прошла на собранном из рабочего дерева образе, с каталогом пробы, смонтированным только для чтения, и с сетью контейнера `none`.
- На итоговом ревью обнаружен пробел в тесте идентификатора. В проверке отложенного построения вызов проведён через `get_feature_realtime_publisher(manager)`. Она сопоставляет идентификатор из переданного или созданного издателем контекста с кадром, который получил сокет. Производственный код при этом не менялся.
- При контрольной подмене `eventId` исключительно в памяти тестового процесса проверка упала на сравнении `different_id` с ожидаемым `evt_shared`. Затем полный backend pytest с обычной реализацией завершился с результатом **866 passed, 338 skipped**. Пропуски относятся к отдельному режиму тестирования с БД.
- Штатный `.\infra\db-tests.cmd` завершился с кодом 0 при отдельном запуске. Полный запуск `python -m pytest tests/integration_tests` в изолированном Compose-проекте B4 с тестовой PostGIS дал **338 passed**. При первой попытке штатного запуска Compose досрочно остановил контейнер с pytest при завершении параллельной сетевой пробы на образе того же проекта. Результат первой попытки исключён из приёмки.
- Проверено подключение lifespan фикстуры AR-02 в тестовом окружении. Браузерный сценарий AR-02 целиком в этот прогон не входил.
- Для всех 30 изменённых или новых Python-файлов backend прошли Black и Ruff. При сравнении синтаксических деревьев с исходной ревизией совпали определения менеджера, подписки, кадра очереди и DTO пользователя. Исправлены пути в карте файлов проекта, `check-memory-needed.py --check` прошёл. Pytest выдал предупреждения об устаревших зависимостях Starlette/AnyIO и passlib/crypt.
