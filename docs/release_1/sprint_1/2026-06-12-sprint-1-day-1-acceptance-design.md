# Спринт 1, День 1: Сценарий Приемки

Дата: 2026-06-12
Статус: подтвержден пользователем

## Назначение

Этот документ является источником истины для наблюдаемого поведения первого
участка Спринта 1:

```text
Login -> Мои наряды -> Create/Open EditVersion -> Edit Workspace
```

Сценарий подтверждает, что назначенный `Editor` может открыть изолированный
read-only workspace на воспроизводимых demo-данных. Изменение сети, validation,
reconcile, review и post остаются за границей Спринта 1.

Связанные артефакты:

- [Доменная модель](2026-06-12-sprint-1-day-1-domain-model-design.md)
- [API-контракт](2026-06-12-sprint-1-day-1-api-contract-design.md)
- [Вертикальный backlog](2026-06-12-sprint-1-day-1-vertical-backlog-design.md)

## Предусловия

- загружен воспроизводимый seed `synthetic_utility_feeder_01`;
- существует активный пользователь `alexey.editor` с ролью `Editor`;
- существует активный пользователь `marina.reviewer` с ролью `Reviewer`;
- `WO-001` назначен `alexey.editor`;
- `WO-001` связан с одним `AOI` и одним `Feeder`;
- существует текущая authoritative revision `Default`;
- у `WO-001` отсутствует активная `EditVersion`.

## Основной Сценарий

### AC-01. Вход И Список Задач

1. `alexey.editor` входит в систему.
2. Система выдает Bearer token.
3. Пользователь открывает `Мои наряды`.
4. Система показывает только назначенные ему work orders, включая `WO-001`.

Критерии:

- список не содержит задачи других пользователей;
- карточка `WO-001` содержит идентификатор, название, состояние и краткое
  описание `AOI`;
- весь пользовательский текст отображается на русском языке.

### AC-02. Первое Открытие Work Order

1. `alexey.editor` открывает `WO-001`.
2. Система атомарно проверяет роль, назначение и состояние `WorkOrder`.
3. Система создает одну активную `EditVersion`.
4. Система фиксирует текущую revision `Default` как `baseRevision`.
5. `WorkOrder` переходит из `Assigned` в `InProgress`.

Критерии:

- новая `EditVersion` возвращается с HTTP `201`;
- `EditVersion` принадлежит `WO-001` и `alexey.editor`;
- создание version и фиксация `baseRevision` происходят в одной транзакции;
- частично созданная version невозможна.

### AC-03. Повторное Открытие

1. `alexey.editor` повторно открывает `WO-001`.
2. Система находит существующую активную `EditVersion`.
3. Система возвращает ее без создания дубля.

Критерии:

- существующая `EditVersion` возвращается с HTTP `200`;
- идентификатор и `baseRevision` совпадают с первым открытием;
- параллельные повторные запросы не создают вторую активную version.

### AC-04. Загрузка Workspace

1. Frontend запрашивает workspace активной `EditVersion`.
2. Backend возвращает `WorkOrder`, `EditVersion`, `AOI`, `Feeder` и read-only
   участок сети.
3. Карта позиционируется по extent `AOI`.
4. Пользователь видит состояние version и границу рабочей области.

Критерии:

- возвращаются только `NetworkFeature` выбранного `Feeder`, пересекающие `AOI`;
- геометрия пересекающих объектов не обрезается по границе `AOI`;
- возвращаются только те `NetworkAssociation`, оба конца которых присутствуют
  в ответе;
- workspace не содержит команд изменения сети;
- пользовательские подписи и ошибки отображаются на русском языке.

## Защитные Сценарии

### AC-05. Чужой Work Order

Пользователь не видит чужой `WorkOrder` в списке. Прямой запрос к чужому или
несуществующему `workOrderId` возвращает одинаковый HTTP `404`, чтобы не
раскрывать существование чужой задачи.

Система не создает `EditVersion` и пишет безопасное русскоязычное событие в
журнал без token, пароля и лишних персональных данных.

### AC-06. Неверная Роль

`Reviewer` может войти в систему, но не получает editor workspace. Попытка
открыть `WorkOrder` или workspace возвращает HTTP `403` с устойчивым
машиночитаемым кодом и русским сообщением.

### AC-07. Некорректный Доменный Контекст

Создание или загрузка workspace отклоняется, если:

- `WorkOrder` находится в несовместимом состоянии;
- отсутствуют обязательные `AOI`, `Feeder` или `Default`;
- `AOI` имеет некорректную geometry;
- данные сети нарушают базовую ссылочную целостность;
- запрос содержит некорректные параметры.

HTTP `409` используется для конфликта состояния, HTTP `422` — для некорректных
данных или параметров. Защитный отказ не оставляет частичных изменений.

## Язык И Журналирование

- весь текст, видимый пользователю, пишется на русском языке;
- сообщения application logs пишутся на русском языке;
- API paths, JSON keys, error `code`, типы, UUID и `correlationId` остаются на
  английском;
- термины `WorkOrder`, `EditVersion`, `AOI`, `Feeder` и `Default` не
  переводятся внутри технических идентификаторов;
- password, Bearer token и секреты не записываются в журнал;
- каждое защитное событие содержит `correlationId`, actor id, operation и
  итог, если эти значения безопасно известны.

## Критерий Завершения Спринта

Acceptance пройден, если после чистого demo seed основной сценарий дважды дает
один и тот же результат, а AC-05, AC-06 и AC-07 подтверждают отсутствие
несанкционированного доступа, дублирующих version и частичных изменений.
