# Отзыв пакета перед публикацией

Решение условной организации; внешние опоры и альтернативы находятся в RAW. Новое правило не реализует submit/review/post.

## Inputs

Точный packageId и цикл review, назначение/полномочие инициатора, причина, snapshot и approval, актуальные blockers, конкурирующая post-попытка и её установленный исход.

## Rule

1. Назначенный активный Editor может отозвать свою подачу без согласия Reviewer. Координатор вправе сделать это при отмене задания в своей области ответственности. Бывший исполнитель сообщает проблему, но не обходит доступ. Reviewer сохраняет четыре решения; отзыв — отдельное действие над намерением.
2. Владелец публикации обеспечивает однозначный порядок принятия отзыва и допуска конкретной post-попытки. Если отзыв принят первым, post этого пакета запрещён. Ранее прочитанный can_post=true не резервирует право. Полномочия, approval, freshness, blockers и отсутствие отзыва проверяются при допуске.
3. Если post допущен первым, запрос отзыва фиксируется без обещания остановки; новые попытки запрещены до установления исхода. Успех ведёт к коррекции; доказанное окончание без эффекта позволяет завершить отзыв. Доказательство исключает поздний эффект ещё живого исполнителя. Timeout и чтение «пока эффекта нет» недостаточны.
4. Для пакета нет двух одновременно неразобранных попыток. Установление неизвестного исхода не является новым намерением публикации. Механизм безопасного выяснения результата проектируется отдельно.
5. Принятый отзыв терминален для конкретного пакета (доменный термин withdrawn). Snapshot и approval сохраняются исторически. Новая подача — новый пакет с новым подтверждением цели, проверками и решением Reviewer, даже при совпавшем checksum. Evidence переиспользуется только после проверки применимости.
6. Повторный отзыв не создаёт повторного перехода/side effects. Отзыв не выполняет Revert, не меняет baseline и не открывает отменённый WorkOrder. Продолжение EditVersion подчинено прежним assignment/lifecycle/token guards.

## Decision Outcome

Принятый отзыв с запретом post; либо запрос с удержанием новых попыток до установления outcome; либо поздний запрос после публикации с переходом к разбору коррекции. Записываются инициатор и полномочие на момент действия, причина, решение, порядок относительно попытки, исход и уведомление Reviewer.

## Exceptions

Факт допуска попытки не является durable post_authorized для будущих вызовов. Новые enum Save, distributed transaction или API не назначены. Если внешний publisher не позволяет доказать порядок/исход, гарантированный отзыв уже переданной работы не обещается. Отмена задания определяет точный набор затронутых пакетов, а не скрыто отзывает всё по AOI.
