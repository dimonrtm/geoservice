# Целевые времена для Utility GIS editor

## Контекст

Для варианта использования `Utility GIS editor` целевые времена нужно задавать не как «всё быстро», а как SLO для пользовательского контура редактирования:

1. открыть карту;
2. перейти к рабочему участку сети / AOI;
3. внести edit;
4. сохранить edit;
5. выполнить validation;
6. выполнить reconcile с Default;
7. разобрать conflicts, если они есть;
8. выполнить post в authoritative state.

Сценарий предполагает branch-like workflow: редактор получает work order, работает в named version, валидирует topology, делает reconcile с Default, разбирает conflicts и только потом публикует изменения через post в Default.

Главное допущение: для `Utility GIS editor` важнее не «быстро любой ценой», а безопасно довести edit до authoritative state без silent overwrite, неверной топологии сети и непонятных конфликтов.

---

## Целевые времена

| Операция | Целевое время для нормального случая | Верхняя граница для acceptance criteria | Почему так |
|---|---:|---:|---|
| Загрузка карты | до 3 сек до видимой рабочей карты | до 5 сек P95 | Редактор должен быстро открыть work order и увидеть участок сети. Полная подгрузка всех вторичных слоёв может продолжаться лениво. |
| Переход к объекту / AOI | до 1 сек | до 2 сек P95 | Для utility-сценария важнее не вся карта города, а быстрый переход к feeder, участку трубы, кабельной линии или наряду. |
| Сохранение одного edit | до 1 сек | до 2 сек P95 | Сохранение атрибута, геометрии или связи должно давать быстрый feedback. Пользователь не должен ждать reconcile/post после каждого edit. |
| Сохранение небольшого набора edits | до 3 сек для 5–20 объектов | до 5 сек P95 | Типичный work order может менять не один feature, а линию, устройство, связь и атрибуты. |
| Validation / topology check | до 5 сек для малого AOI | до 15 сек P95 | Validation тяжелее обычного save, потому что проверяет связность, правила сети, dirty areas и ассоциации. |
| Reconcile без конфликтов | до 5 сек | до 10 сек P95 | Операция должна быть достаточно быстрой, чтобы пользователь не откладывал reconcile «на потом». |
| Reconcile с конфликтами | до 10 сек до показа списка конфликтов | до 20 сек P95 | Система не обязана автоматически решить конфликт, но обязана быстро показать, что именно конфликтует: объект, атрибут, геометрия, delete/update. |
| Открытие conflict view / diff | до 2 сек | до 5 сек P95 | Главная ценность — осмысленное разрешение конфликта, а не просто сообщение «ошибка reconcile». |
| Post в Default / authoritative state | до 5 сек | до 15 сек P95 | Post должен быть короткой финальной операцией после успешного reconcile и validation. |
| Повторный post после изменения Default | ошибка до 3 сек | до 5 сек P95 | Если Default изменился после reconcile, пользователь должен быстро получить понятное требование повторить reconcile, а не долгий зависший post. |

---

## Минимальные целевые пороги для MVP

```text
Map load to usable AOI:              <= 5 sec P95
Jump to object / AOI:                <= 2 sec P95
Save single edit:                    <= 2 sec P95
Save 5–20 edits:                     <= 5 sec P95
Validate AOI/topology:               <= 15 sec P95
Reconcile no conflicts:              <= 10 sec P95
Reconcile with conflicts view:       <= 20 sec P95
Open conflict diff view:             <= 5 sec P95
Post to Default:                     <= 15 sec P95
Post rejected after stale Default:   <= 5 sec P95
```

## Acceptance criteria

### AC-01. Загрузка карты

**Given** пользователь с ролью `Utility GIS editor` открывает work order на малом synthetic utility dataset
**When** система открывает карту и позиционируется на рабочий AOI
**Then** карта должна стать пригодной к работе не дольше чем за `5 секунд P95`.

Карта считается пригодной к работе, если:

- виден рабочий AOI;
- видны основные utility-объекты;
- пользователь может выбрать объект;
- интерфейс не заблокирован полной подгрузкой вторичных слоёв.

---

### AC-02. Переход к объекту или AOI

**Given** карта уже открыта
**When** пользователь выбирает work order, feeder, участок сети или конкретный объект
**Then** переход к нужному AOI должен занимать не больше `2 секунд P95`.

---

### AC-03. Сохранение одного edit

**Given** пользователь изменил один объект: атрибут, геометрию или связь
**When** он нажимает `Save`
**Then** сохранение должно завершиться не дольше чем за `2 секунды P95`.

После сохранения пользователь должен видеть:

- что edit принят в его рабочую версию;
- что объект имеет актуальное локальное состояние;
- что дальнейшие операции validation/reconcile/post ещё не выполнены, если они действительно не выполнены.

---

### AC-04. Сохранение небольшого набора edits

**Given** пользователь в рамках одного work order изменил от 5 до 20 объектов
**When** он сохраняет набор изменений
**Then** сохранение должно завершиться не дольше чем за `5 секунд P95`.

---

### AC-05. Validation / topology check

**Given** пользователь сохранил edits в рабочей версии
**When** он запускает validation по рабочему AOI
**Then** validation должна завершиться не дольше чем за `15 секунд P95`.

Validation должна показать один из результатов:

- topology valid;
- найдены dirty areas;
- найдены ошибки связности;
- найдены ошибки правил сети;
- найдены ошибки ассоциаций.

---

### AC-06. Reconcile без конфликтов

**Given** рабочая версия содержит сохранённые edits
**And** Default не содержит конфликтующих изменений
**When** пользователь запускает reconcile
**Then** reconcile должен завершиться не дольше чем за `10 секунд P95`.

После успешного reconcile система должна явно показать, что версия готова к post, если validation также успешна.

---

### AC-07. Reconcile с конфликтами

**Given** рабочая версия содержит edits
**And** Default содержит конфликтующие изменения по тем же объектам, атрибутам или геометрии
**When** пользователь запускает reconcile
**Then** система должна показать список конфликтов не дольше чем за `20 секунд P95`.

Список конфликтов должен различать минимум следующие типы:

- attribute/update conflict;
- geometry/update conflict;
- update/delete conflict;
- conflict by object;
- conflict by attribute.

---

### AC-08. Conflict view / diff

**Given** reconcile обнаружил конфликты
**When** пользователь открывает конкретный конфликт
**Then** conflict view должен открыться не дольше чем за `5 секунд P95`.

Conflict view должен показывать:

- версию пользователя;
- состояние Default;
- конфликтующее поле или геометрию;
- тип конфликта;
- доступное действие: принять свою версию, принять Default, выполнить ручное исправление.

---

### AC-09. Post в authoritative state

**Given** validation успешна
**And** reconcile успешен
**And** не осталось unresolved conflicts
**When** пользователь выполняет post в Default
**Then** post должен завершиться не дольше чем за `15 секунд P95`.

После post система должна показать, что изменения опубликованы в authoritative state.

---

### AC-10. Post при устаревшем Default

**Given** пользователь уже выполнил reconcile
**And** после этого другой пользователь изменил Default
**When** пользователь пытается выполнить post
**Then** операция должна завершиться контролируемой ошибкой не дольше чем за `5 секунд P95`.

Сообщение должно явно объяснять:

- что Default изменился после последнего reconcile;
- что нужен повторный reconcile;
- что изменения пользователя не потеряны.

---

## Итоговая формулировка

Для малого synthetic utility dataset карта должна становиться пригодной к работе за `≤5 секунд P95`. Один edit должен сохраняться за `≤2 секунды P95`. Сохранение набора из 5–20 edits должно укладываться в `≤5 секунд P95`. Validation по рабочему AOI должна завершаться за `≤15 секунд P95`. Reconcile без конфликтов должен завершаться за `≤10 секунд P95`, а reconcile с конфликтами должен показать список конфликтов за `≤20 секунд P95`. Post после успешного reconcile и validation должен завершаться за `≤15 секунд P95`. Если Default изменился после reconcile, post должен завершиться контролируемой ошибкой за `≤5 секунд P95` с понятным требованием повторить reconcile.

Главная мысль: для `Utility GIS editor` save должен быть быстрым, а validation/reconcile/post могут быть чуть дольше, но обязаны быть предсказуемыми, объяснимыми и безопасными для authoritative state.
