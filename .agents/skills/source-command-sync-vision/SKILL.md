# /sync-vision

`/sync-vision` синхронизирует состояние wiki. Он не переписывает смысл нод без отдельного запроса.

## Когда Запускать

- Утром перед работой.
- После крупного `/ingest`.
- Перед встречей или демо.
- Раз в неделю перед отчетом о здоровье wiki.

## Шаг 1. Собрать Изменения

Проверить изменения в:

- `RAW_inputs/`
- `Vision_wiki/`
- `Code_wiki/`
- `memory/`
- `Общие_принципы/`
- `docs/knowledge-pipeline/`

Можно использовать:

```powershell
git log --since="7 days ago" --pretty=format:"%h %ad %s" --date=short -- RAW_inputs/ Vision_wiki/ Code_wiki/ memory/ Общие_принципы/
```

## Шаг 2. Обновить Индексы

Для каждой wiki-области:

- перечитать `index.md` и `_info.md`;
- добавить ссылки на новые значимые ноды;
- убрать ссылки на удаленные файлы;
- обновить ссылки после переименований;
- сохранить структуру Obsidian wikilinks.

Корневой `index.md` должен показывать:

- основные области знаний;
- свежие важные изменения;
- открытые вопросы;
- ссылку на `memory/project-state.md`.

## Шаг 3. Посчитать Состояние Wiki

Собрать:

- количество новых RAW inputs;
- количество новых concept/decision/entity/solution нод;
- открытые follow-up'ы;
- unresolved conflicts;
- stale-ноды;
- результаты последнего `/lint-wiki`.

## Шаг 4. Пометить Stale

Если нода давно не обновлялась или выглядит устаревшей:

- не удалять ее;
- добавить `stale` в `tags`;
- при необходимости добавить follow-up в `Vision_wiki/decisions/followups/index.md`.

## Шаг 5. Обновить `memory/project-state.md`

Добавить раздел или строку:

- дата и время последнего `/sync-vision`;
- что изменилось с прошлого sync;
- открытые вопросы;
- stale-ноды;
- что требует решения пользователя.

## Шаг 6. Доложить Пользователю

Кратко:

- что нового найдено;
- какие индексы обновлены;
- какие вопросы требуют внимания;
- нужно ли запускать `/ingest`.

## Ограничения

- Не редактировать смысл старых нод без отдельного запроса.
- Не закрывать конфликты самостоятельно.
- Не менять код, конфигурацию, миграции и тесты.
- Wiki-контент вести на русском языке.
