# Объединённая проверка M4

Два сценария выполняют Save/Revert через настоящий UI, скрывают настоящий success после commit, перезапускают API, обновляют ту же вкладку и проверяют replay, отдельный GET и отсутствие дополнительной mutation.

Требуются Docker Compose, Node.js и свободные loopback-порты 15173/18180. Из этого каталога:

```powershell
npm.cmd ci
npx.cmd playwright install chromium
npm.cmd test
```

В Linux команды npm/npx используются без `.cmd`. Тестовый пакет отделён от приложения. Chromium и npm-зависимости устанавливаются один раз; Docker собирает текущий исходный код.

Runner создаёт уникальный проект `geoservice-m4-<id>`. PostGIS хранит отдельную `m4_test` в tmpfs. Миграции и seed исполняются до тестов; restart запускает только uvicorn. БД сохраняется при restart API. В `finally` удаляются только контейнеры и сеть этого запуска. Пользовательские demo-контейнеры не используются. При принудительном завершении runner оставшийся проект можно найти через `docker compose ls` и удалить по его точному имени; не использовать глобальный prune.

Состояние сбоя принадлежит browser context и переживает reload. После первого commit повторные PUT блокируются перед backend. Барьер открывается при новой навигации той же вкладки после restart. Тест не изменяет storage и не вызывает actions store напрямую. Координаты клика рассчитываются по AOI и реальному canvas; перемещение вершины выполняется мышью.

Проверяются три снимка БД: до команды, после первого commit, после replay. В evidence записываются revision, события, количество записей команд, baseline, geometry, исходная команда и порядок запросов. Проверка actor сопоставляет JWT subject, owner версии и recovery record; обновление access token при refresh допустимо. Исходный draftVersionToken команды неизменен. Traces и видео отключены, чтобы не сохранять токены.

Успешный прогон сохраняет JSON и скриншоты в `docs/sprint_2/evidence/day-12/m4/`. При ошибке Playwright пишет диагностику в игнорируемый `test-results/`. Старый успешный evidence сам по себе не подтверждает новый прогон: проверять exit code и `verifiedAt`/имя проекта в JSON. Сценарии не используют автоматические retries тестов.

Физическое отключение сети, crash БД, повторный вход и восстановление после потери доступа не входят в этот набор. Принятые границы: [спецификация](../../docs/sprint_2/2026-10-20-day-12-recovery-design.md).
