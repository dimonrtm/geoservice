# Объединённая проверка M4

Два исходных сценария выполняют Save/Revert через настоящий UI, скрывают настоящий success после commit, перезапускают API, обновляют ту же вкладку и проверяют replay, отдельный GET и отсутствие дополнительной mutation.

Требуются Docker Compose, Node.js и свободные loopback-порты 15173/18180. Из этого каталога:

```powershell
npm.cmd ci
npx.cmd playwright install chromium
npm.cmd test
```

В Linux команды npm/npx используются без `.cmd`. Тестовый пакет отделён от приложения. Chromium и npm-зависимости устанавливаются один раз; Docker собирает текущий исходный код.

Runner создаёт уникальный проект `geoservice-m4-<id>`. PostGIS хранит отдельную `m4_test` в tmpfs. Миграции и seed исполняются до тестов; restart запускает только uvicorn. БД сохраняется при restart API. В `finally` удаляются только контейнеры и сеть этого запуска. Пользовательские demo-контейнеры не используются. При принудительном завершении runner оставшийся проект можно найти через `docker compose ls` и удалить по его точному имени; не использовать глобальный prune.

Состояние сбоя принадлежит browser context и переживает reload. После первого commit повторные PUT блокируются перед backend. Барьер открывается при новой навигации той же вкладки после restart. Тест не изменяет storage и не вызывает actions store напрямую. Координаты клика рассчитываются по AOI и реальному canvas; перемещение вершины выполняется мышью.

Проверяются три снимка БД: до команды, после первого commit, после replay. В evidence записываются revision, события, количество записей команд, baseline, geometry, исходная команда и порядок запросов. Проверка actor сопоставляет JWT subject, owner версии и recovery record; обновление access token при refresh допустимо. Исходный draftVersionToken команды неизменен. Traces и видео отключены, чтобы не сохранять токены.

Успешный прогон сохраняет JSON и скриншоты в `docs/sprint_2/evidence/s2-x01/legacy-m4/`. При ошибке Playwright пишет диагностику в игнорируемый `test-results/`. Старый успешный evidence сам по себе не подтверждает новый прогон: проверять exit code и `verifiedAt`/имя проекта в JSON. Сценарии не используют автоматические retries тестов.

## Дополнение S2-X01

Пять дополнительных сценариев проверяют:

- Save и Revert после настоящего закрытия и нового запуска Chromium с тем же persistent profile/origin; storageState не экспортируется и recovery создаёт само приложение.
- Независимые A/B/C, поздний replay старого Save при более новом current, другого actor и отдельное согласие для каждого recovery после повторного входа. Более новый Save в занятой версии отправляет тестовый HTTP-драйвер; пользовательский UI guard не обходится.
- Реальный отзыв назначения: тестовый наряд назначается другому синтетическому editor; API возвращает `404 EDIT_VERSION_NOT_FOUND`. Возвращение назначения само не запускает replay. Счётчики после явного согласия совпадают с первым commit.
- Настоящий IndexedDB: CAS/abort, независимые ключи, повреждённая запись только своего контекста, изоляция actor и receipt прерванного v1-import.

A/B/C и второй actor создаются только в `m4_test` до измерения. Отдельный access-test меняет только назначение для моделирования реального отзыва/возврата; не переписывает geometry/revision/events. Новые JSON и screenshots находятся в `docs/sprint_2/evidence/s2-x01/`. Исторический evidence Дня 12 не перезаписывается. В screenshot-проходе проверяются шесть viewport, отсутствие горизонтального overflow страницы, read-only preview, Tab/Shift+Tab/Escape и возврат фокуса диалога. Узкая таблица и панель сравнения прокручиваются внутри своих областей; reflow не означает настоящий zoom 200%.

Для одного сценария runner передаёт аргументы Playwright:

```powershell
node run.mjs --grep "real assignment loss"
```

Persistent profiles остаются в игнорируемом `test-results/` для диагностики; это disposable тестовые профили с синтетическими аккаунтами. Не публиковать их и traces. Не удалять произвольные пользовательские browser profiles.

Физический сетевой разрыв, crash БД, уничтожение browser storage и координация вкладок не проверяются. Границы: [спецификация S2-X01](../../docs/sprint_2/2026-10-23-s2-x01-recovery-design.md).
